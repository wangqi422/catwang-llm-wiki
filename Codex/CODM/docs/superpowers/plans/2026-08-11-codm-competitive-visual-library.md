# CODM Competitive Visual Library Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a responsive CODM competitive-poster intelligence H5 that converts four damaged manifests into one searchable, filterable, source-traceable visual library.

**Architecture:** A repeatable Node normalization script copies and repairs the four source manifests into a typed normalized dataset plus a repair report. A Vite + React + TypeScript client consumes only the normalized local JSON, keeps filters in the URL, stores favorites/view preferences in local storage, and renders a responsive Dark Ops gallery with a keyboard-accessible lightbox.

**Tech Stack:** Node.js, Vite, React, TypeScript, Vitest, Testing Library, CSS, local JSON, Playwright/browser visual verification.

## Global Constraints

- Do not overwrite the four source manifests.
- Keep encoding repair separate from editorial content rewriting.
- Use `#0D0D0D` page background, `#141414` cards, `#FFE600` primary accent, sharp corners, no box shadows, and at most one secondary accent color.
- The build is frontend-only and must not write to external systems.
- Desktop uses a fixed filter rail and dense 4–6 column gallery; 390 × 844 mobile uses a two-column gallery and filter drawer.
- Search, filters, favorites, reset, detail lightbox, source navigation, and available original-image download must work.
- Do not silently discard parse failures; record them in `public/data/repair-report.json`.
- Final handoff requires `design-qa.md`; P0/P1/P2 issues must be fixed. If reference capture remains unavailable, the report must say `final result: blocked`.

- [ ] **Step 3: Implement deterministic repair and normalization**

The script must:

1. Read exact input paths passed through CLI arguments.
2. Preserve source files unchanged.
3. First call `JSON.parse`; only on failure repair lines with an unmatched value quote by inserting `"` before the final comma or line ending.
4. Attempt reversible mojibake recovery only when a round trip is lossless; otherwise retain the original field.
5. Infer `sourceType` from `is_kv`, YouTube URL/video ID, ArtStation URL, or `other`.
6. Prefix duplicate IDs with a stable slug derived from the source filename.
7. Skip only records without a usable `card`, `card_url`, `original`, or `orig_url` and record the reason.
8. Sort by source file order then original record order.
9. Write totals, repaired lines, duplicate IDs, skipped records, and field-missing counts to `repair-report.json`.

The CLI must accept:

```text
node scripts/normalize-manifests.mjs --out public/data <manifest1> <manifest2> <manifest3> <manifest4>
```
