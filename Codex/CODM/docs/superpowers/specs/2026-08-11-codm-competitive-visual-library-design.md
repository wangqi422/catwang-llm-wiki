# CODM 竞品视觉情报库 H5 设计说明

## 1. 项目目标

将四份竞品海报 manifest 汇总为一个可直接在浏览器使用的 H5，帮助游戏宣发与视觉团队快速完成竞品素材浏览、搜索、筛选、回源和下载。

首版聚焦“找图效率”和“来源可信度”，不扩展为复杂的多人素材管理系统。

## 2. 输入数据

| 数据文件 | 约计条目 | 主要内容 |
| --- | ---: | --- |
| `manifest.json` | 143 | 综合游戏宣传素材、YouTube 封面、官方 KV |
| `manifest_artstation.json` | 152 | ArtStation 项目与作品图 |
| `manifest_battlefield_yt.json` | 74 | Battlefield YouTube 宣传素材 |
| `manifest_kv.json` | 67 | COD、Delta Force、Rainbow Six、Arena 等官方 KV |

合计约 436 条。部分文件存在中文乱码及乱码导致的 JSON 引号损坏，不能直接作为前端运行时数据源。

## 3. 数据处理边界

### 3.1 原始文件保护

- 不覆盖四份原始 manifest。
- 原始文件只作为输入和问题追踪依据。
- 在项目内生成清洗后的统一数据文件。

### 3.2 编码修复

- 编码修复与内容改写分开执行。
- 可确定的 UTF-8/GBK 逆转码乱码进行恢复。
- 无法可靠恢复的中文保留英文标题、来源标识或中性占位名称，不猜测原文。
- 修复脚本输出解析成功率、丢弃条目和字段缺失报告。

### 3.3 统一数据模型

每条素材转换为以下字段：

```text
id              唯一 ID
title           标题
game            游戏或产品线
source          来源名称
sourceType      official_kv / youtube / artstation / other
sourceUrl       原始页面地址
category        scene / character / weapon / brand_promo / brand_collab / other
thumbnail       卡片预览图
original        原图地址或本地原图路径
videoId         YouTube 视频 ID
dimensions      图片尺寸（可用时）
hasPrompt       是否包含提示词
prompt          已有提示词
is4k            是否为 4K 原图
searchText      供前端搜索使用的标准化文本
```

## 4. 信息架构

### 4.1 顶部导航

- 产品名称：`CODM COMPETITIVE INTEL`
- 数据概览：素材总数、来源数、4K 数量、带提示词数量
- 搜索框：搜索标题、游戏、来源与分类
- 视图切换：网格密度切换
- 收藏入口：只看收藏

### 4.2 筛选区

- 游戏：COD、Battlefield、Delta Force、Rainbow Six、Arena Breakout 等
- 来源类型：官方 KV、YouTube、ArtStation、其他
- 内容类别：场景、角色、武器、品牌宣传、联动
- 质量状态：4K、含原图、含提示词
- 当前筛选条件以可单独移除的标签显示
- 支持一键重置

桌面端使用左侧固定筛选栏；移动端改为底部抽屉，避免占用图库宽度。

### 4.3 素材图库

- 桌面端采用高密度自适应网格。
- 移动端采用双列卡片。
- 图片保持原始比例，避免强行裁成统一横图。
- 卡片显示游戏、来源类型、标题、4K/提示词等状态。
- 悬停或点击出现收藏、打开来源、查看详情操作。
- 采用渐进加载和分页/增量加载，避免一次加载全部图片。

### 4.4 详情灯箱

- 高清图片居中展示，背景降噪。
- 支持适应窗口、1:1、放大、缩小和拖动。
- 展示标题、游戏、来源、分类、尺寸和质量状态。
- 支持复制来源链接、打开原始页面和下载可用原图。
- YouTube 条目优先打开对应视频；ArtStation 条目打开项目页。
- 有提示词时可展开并复制，不在默认状态占用大量空间。

## 5. 视觉语言

以现有 v17 的暗色军事情报库语言为基础：

- 背景：接近黑色的分层灰 `#0D0D0D`、`#141414`、`#1B1B1B`
- 强调色：CODM 黄 `#FFE600`
- 主文字：`#F2F2F2`
- 次要文字：`#8B8B8B`
- 成功/高清状态：低饱和绿色
- 卡片使用细边框、轻微抬升和克制阴影，不使用大面积玻璃拟态
- 字体优先使用系统无衬线字体，数字和标签可使用紧凑字宽
- 动效控制在 120–220ms，强调快速浏览，不做干扰性粒子或装饰动画

## 6. 状态与交互

- 搜索与筛选即时生效，并显示结果数量。
- 收藏、已查看条目和网格密度保存在浏览器本地。
- URL 查询参数记录搜索与筛选状态，便于分享当前视图。
- 图片失败时显示来源类型与标题，不使用空白破图图标。
- 无结果状态提供重置筛选操作。
- 所有可点击控件提供清晰 hover、focus 和 active 状态。
- 键盘支持 `Esc` 关闭灯箱、方向键切换素材、`F` 收藏。

## 7. 技术结构

采用自包含的前端原型：

- Vite + React + TypeScript
- `src/data/`：清洗后的统一 JSON
- `scripts/normalize-manifests.*`：可重复执行的数据转换脚本
- `src/components/`：导航、筛选、图库、卡片、灯箱等独立组件
- `src/lib/`：搜索、筛选、URL 状态和本地存储逻辑
- 不依赖后端，不写入外部系统
- 图片资源优先使用可访问的真实来源；最终构建不使用未经确认的热链资产

## 8. 错误处理

- 构建数据前校验 ID、标题、图片地址和来源地址。
- 重复 ID 使用来源前缀生成稳定新 ID，并写入报告。
- 无图片条目进入数据报告，默认不进入图库。
- 解析失败条目不静默丢弃，记录文件名和附近文本位置。
- 前端对图片加载失败、来源缺失和下载不可用提供明确状态。

## 9. 响应式规则

- ≥ 1280px：左侧筛选栏 + 4–6 列网格。
- 768–1279px：收窄筛选栏 + 3–4 列网格。
- < 768px：顶部搜索、双列图库、底部筛选抽屉。
- 390 × 844 为移动端主要验收视口。
- 灯箱工具栏在移动端收敛为主要操作，不遮挡图片主体。

## 10. 验收标准

- 清洗后数据可被标准 JSON 解析器完整读取。
- 页面能展示来自四份 manifest 的有效素材，并给出汇总数量。
- 搜索、游戏筛选、来源筛选、分类筛选、收藏和重置可用。
- 详情灯箱、原始来源跳转和可用原图下载可用。
- 桌面和 390 × 844 移动端不存在横向溢出、控件遮挡或严重裁图。
- 主要交互无浏览器控制台错误。
- 生成 `design-qa.md`，P0/P1/P2 问题全部修复，最终结果为 `passed`；若参考页无法捕获，则明确记录为 `blocked`，不虚报视觉复刻通过。

## 11. 首版不包含

- 登录、云端收藏和多人协作。
- 在线上传、删除或编辑原始素材。
- 自动视觉理解、相似图检索和 AI 标签生成。
- 后端爬虫调度与定时采集。
- 未经授权的第三方素材重新托管。

这些能力可在首版稳定后按实际使用频率评估。
