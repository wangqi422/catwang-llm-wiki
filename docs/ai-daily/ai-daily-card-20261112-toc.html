判断、界面、单细胞 —— Google 一天把「模型该输出什么」拆成了三份
1 Google 发布 Gemini Decision 1 与 Gemini Decisions API：不逐 token 生成，单次前向传播评 1000 题，150–250ms / $0.10 每百万输入 🧭 决策模型 / 新品类 / 低延迟低成本
北京时间 11 月 12 日凌晨（当地时间 11 月 11 日），Google 在 Google AI Studio 正式推出 Gemini Decisions API，由全新的 Gemini Decision 1 模型驱动。与传统生成式大模型逐 token 生成文字不同，这款模型专为封闭选项集里的决策任务设计：不解码答案，而是通过单次前向传播对预设候选答案评分，直接返回判断结果、概率与置信度。官方口径下，可在 150–250ms 端到端延迟内，对文本、图像、音频、视频与 PDF（最多 256K tokens）一次性评估最多 1000 个是 / 否判断、多选（最多 255 选项）或打分题。定价为每百万输入 token $0.10、输出 token 费用为零，约为 Flash-Lite 的五分之一。Sundar Pichai 在 X 发文介绍并展示 Stitch Rapid 几秒内设计完整产品流程（1 倍速）；模型已上线 OpenRouter，Artificial Analysis 的 Decision Index 给出 66 分，中文媒体口径为「9 项测试拿下 7 项第一、准确率最高 92.2%」。把「判断」从「生成」里拆出来是一个新品类：过去想让 AI 判断一封邮件是不是垃圾邮件、或决定一项任务交给哪个 Agent，要调生成式模型再从文本里抽结果，现在省掉整套解码。与 #2 A2UI、#3 AlphaGenome 2 是同一天的同构动作——Google 没有再堆一个「更能生成」的通用旗舰，而是把输出形态拆成判断、界面、单细胞预测三个专用形态，竞争口径从「会不会答」转向「能不能交付一个可直接用的结果」。边界：9 项 7 第一、92.2%、66 分多为官方或第三方单一口径、无统一独立复测；专为封闭选项集设计、不能生成开放式内容；「校准误差最低」为官方说法。

2 Google 开源 A2UI 1.0 生成式 UI 协议首个稳定版：智能体直接回复原生交互界面，Apache 2.0，Atlassian / Alation / 字节已接入 🧩 生成式 UI / 开放协议 / 原生渲染
北京时间 11 月 12 日（当地时间 11 月 11 日），Google 宣布生成式 UI 开放协议 A2UI 1.0 正式上线，官网已将 v1.0 列为现行版本（首个稳定版，v0.9.1 为上一版）。A2UI 是 Google 于 2025 年底公布的协议，让智能体不只回文字，而是发送声明式组件描述、由客户端用自己的原生组件绘制交互界面——确认表单、图表、选择器都成为新的「回答方式」。项目以 Apache 2.0 开源，由 Google 创建、CopilotKit 与社区贡献。1.0 新增双向函数调用（callAgentFunction / callRendererFunction，航班选择器可在组件内就地核查余位）、无障碍支持（ARIA live region / hidden）、扩展元数据命名空间、allowedParents / allowedChildren 嵌套约束、分级 ValidationResult（错误 / 警告 / 提示）、requiresUserActivation、多目录 catalogId 混合与 @path 动态绑定。开源渲染器覆盖 Web（React / Angular / Lit 稳定）、Flutter（移动 / Web / 桌面）、SwiftUI（iOS）、Jetpack Compose（Android，v1.0 仍为 Planned）；Web 与 Flutter 渲染器可在 MCP Apps 内工作；智能体 SDK 在 Python 之外新增 TypeScript 与 Dart。落地案例：Atlassian 把 A2UI 引入 Jira（工作项内交互卡片补问）、Alation 用其构建指标卡与图表信息流（可展示背后 SQL）、彭博社，以及字节跳动早在 2026 年 6 月就为跨端框架 Lynx 发布 A2UI 渲染器；CopilotKit 同步推出基于 1.0 的 Generative UI（标准目录 70 组件，含 18 个 A2UI 基础组件）。安全分工前置最值得抄：模型只描述「要展示什么」，应用执行渲染，数据与子组件在服务端绑定、敏感数值不进模型；采用声明式数据格式而非可执行代码，从根上避开模型现场写 React / SwiftUI 带来的脚本注入与样式破坏。它不是 MCP / AG-UI / A2A 的替代品，而是补上 UI 载荷这一层——一条任务链可四者协作；与 MCP Apps（服务端预制 HTML + 沙盒 iframe）是两条路线。交付物从「答案」变成「工作节点」，竞争从答案正确率转向任务完成率。边界：版本状态并不整齐（Compose 1.0 Planned、Flutter / SwiftUI Alpha、Gemini Enterprise 仍 0.9.1、ADK Web 集成 v0.8），准确说法是「协议核心进入稳定、生态拿到迁移基准」；官方案例均未给出统一任务完成率与大规模对照数据。

3 Google DeepMind 发布 AlphaGenome 2：从组织平均深入单细胞类型，1.07 亿单细胞图谱 / 68 组织，识别变异能力近翻倍 🧬 基因组 AI / 单细胞 / 科学落地
当地时间 11 月 11 日，Google DeepMind 发布新一代基因组 AI 模型 AlphaGenome 2，能够预测 DNA 序列及其变异对特定人类细胞类型和细胞状态的影响。新模型采用条件模型架构，使用超过 1.07 亿个人类和小鼠单细胞图谱、覆盖 68 种组织训练，识别基因表达相关遗传变异的能力接近上一代两倍，并新增 DNA 甲基化等分子指标预测，支持在不重新训练的情况下分析此前未见过的细胞类型与生物状态。DeepMind 称通过「从广泛的组织平均值深入到单个细胞类型和细胞状态」实现了阶跃式提升，能把静态细胞图谱转化为遗传学的预测引擎——例如解析特定心肌细胞或血液免疫细胞内的活动，帮助发现仅在特定细胞类型中起作用的关键 DNA 变异。官方援引近期研究称，调控开关通过在肠道免疫细胞中过度激活 ETS2 基因驱动炎症性肠病，而 AlphaGenome 2 能在计算层面复现这一发现。目前通过 AlphaGenome API 开放非商业研究，并以私人预览版开放给商业研究。从「平均」到「条件」是能力而非参数量的跃迁：上一代依赖组织平均值、会漏掉疾病相关细胞中的变异效应；条件架构让同一段 DNA 在不同细胞状态下被差异读取，且能外推到训练时未见过的细胞类型。有落地验证，不是纯跑分：复现 ETS2 / 炎症性肠病的已知发现，是「预测能对齐实验结论」的证据。与 #1 / #2 同构：同一天 Google 把「模型该输出什么」拆到判断、界面、单细胞预测三个专用形态，前沿实验室正从「一个模型包打天下」转向「按交付物形态做专用模型」。边界：「接近翻倍」为官方口径、无独立大规模复测；当前仅非商用 API + 商用私人预览；与临床转化之间仍隔实验验证与监管。

4 阿里官宣 Qwen4 与 Qwen4-Max 预览版：代际升级追平第一梯队，兼容 OpenAI / Anthropic 接口，Token Plan 订阅制开放 🚀 国产旗舰 / 多模态 / 接口兼容
阿里正式官宣新一代千问 Qwen4 大模型系列，Qwen4-Max 预览版同步上线，在通用推理、数学代码、多模态理解、长上下文、智能体执行等核心维度完成代际升级，官方称在多项国际基准评测中追平全球第一梯队，同步优化端云协同部署效率，后续逐步释放全系列版本与开源权重。Qwen4-Max 可直接读取页面截图、带图表的文档与视频内容，不必把不同输入拆给不同模型；接口兼容 OpenAI Chat Completions / Responses 以及 Anthropic Messages 格式，存量业务代码迁移成本低；除 API 外还可通过 Qoder、千问办公、千问 App、QwenStudio 多入口体验。需要注意的是，预览版当前仅通过 Token Plan 订阅制开放调用、暂不支持通用按量付费（Credits 统一计量）。适用场景为复杂编程、多步骤 Agent、长文档 / 混合资料分析与专业办公；不适合高并发、低延迟、成本敏感的简单问答（用 Qwen4-Flash / Plus 更划算）。一个容易踩的坑：从该预览模型开始，max_tokens 与 max_completion_tokens 限制的是「思考内容 + 最终回答」的总量，按旧习惯只给最终回答留额度，长推理任务会提前截断。双 11 期间阿里云 Token Plan 两款月卡 5 折起、Qoder 月卡 3.3 折、千问办公基础版首月 3 折起。国产「集中冲顶」里的最新一棒：近一周已有 11-06 百度 ERNIE 5.5 Flash Base 开源、11-10 ERNIE Evolve、小米 MiMo-V2.6，Qwen4 是 Qwen3.8 → Qwen4 的全新系列代际升级（非旧模型继续报道）。接口兼容 + 多入口是冲份额最实在的一招，把迁移成本压到最低。边界：「追平第一梯队」为官方口径、无统一独立复测；预览版非全量开放，开源权重「后续逐步释放」无明确日期；简单任务用旗舰不划算，官方自己给了分流建议。

xAI 发布 Grok Bot 1.0，定位为「可协作的 AI 团队成员」：不再是你去聊天框问一句、它答一句的助手，而是可接入 Slack 与 Microsoft Teams、能被邀请进会议、在团队沟通渠道里与人类同事一起工作的常驻 AI 队友。马斯克本人在 X 上宣传，Grok Bot 工程参与者也介绍了上线细节；AI HOT 聚合池在近 24h 内对该事件有 7 条以上独立命中（发布、可邀入会议、接入 Slack / Teams、团队协作定位等），是当天热度最集中的产品发布之一。同期 Databricks 升级的 Genie 智能体已宣布接入 ChatGPT、Claude、Microsoft Copilot Cowork 与 Grok Bot，企业协作入口的混战正式开打。从「你问它答」到「它在群里」：AI 从「一次性会话」变成「常驻协作渠道的成员」，与 11-11 期 Claude 办公套件（Whiteboards / Sheets / Data）、#2 A2UI「交付物变界面」、#6 入口争夺同属「AI 铺进工位」这条主线的延续——入口不再是聊天框，而是团队本来就在的地方。企业协作入口正在变成多方混战：微软 Copilot Cowork、Anthropic 办公套件、Databricks Genie、xAI Grok Bot 同场，谁占住团队默认打开的那个渠道，谁就拿到后续所有工作流的分发权。权限与数据隔离是硬前提：同一聚合池里还有 Grok 被指生成不当图像面临集体诉讼，以及 Grok Build 分享链接漏洞导致 SpaceXSI 内部资料与数千用户数据公开暴露（安全公司 Claroc 称 94.7% 的 Grok 构建应用可被任意访问）——AI 队友进协作渠道前，能看什么、能发什么、能碰哪些文件必须先收口。边界：核心能力与可用性多为厂商官宣 / 演示口径，无统一任务完成率与大规模企业对照数据；上述安全事件为第三方披露，与 1.0 发布本身需分开看。

腾讯全新搜索产品「元宝搜索」正式上线（36氪获悉），把元宝从 AI 助手向「搜索 + 助手」复合入口补齐。同日有消息称字节跳动计划推出类似 Meta Muse 的 AI 助手、给豆包造一个「超级大脑」（爱范儿 / 36氪报道），并引述张一鸣内部表态：需到 2029 或 2030 年才追平美国顶尖实验室。两条合起来看，中国 AI 入口正从「聊天框」向「搜索 + 超级助手」扩张。这与近 24h 内的其他入口动作同构：OpenAI 的 Businesses in ChatGPT（11-11 期 #6，商家入口）、Gemini 接入 Apple CarPlay（iOS 用户可在车内免提语音对话）、ChatGPT 桌面应用上线财务功能——大家都在抢「用户第一个打开的那个框」。入口的定义在变：过去搜索是「找链接」、助手是「给答案」，现在两者合并成「直接替你完成」；腾讯把元宝补上搜索，是拿自有内容生态 + 检索给 AI 入口加底座。国产阵营第一次给出公开时间锚：张一鸣「2029–2030 追平」在普遍只讲「已追平 / 已超越」的宣传口径里显得少见，也侧面说明超级助手被当作长周期工程而非一次发布。与 #1 / #2 / #5 合看：Decision 1 改「输出什么」、A2UI 改「交付成什么样」、Grok Bot 改「待在哪里」、元宝搜索改「从哪儿进来」——今天所有大动作都在重排「人和 AI 的接口」，而不只是模型能力。边界：元宝搜索的产品细节与覆盖范围为媒体获悉口径；字节「中国版 Muse」仍为消息 / 计划阶段、非已发布产品；张一鸣表态为内部转述。

编辑点评

八条其实在讲同一件事：从会答，到会判、会交、会干活。昨天（11-11 期）比的是「谁能把能力最快最广地铺开」，今天比的换成了「AI 到底该交出什么」——最密集的动作来自 Google 一家，它没再发一个「更能生成」的通用模型，而是把输出形态拆成了判断、界面、单细胞预测三份。今天没有谁在比谁写得多，大家比的是谁交得出东西。

① 上半场是「不生成」三连（#1–#3）。Gemini Decision 1 干脆不逐 token 生成文字，单次前向传播就对最多 1000 个封闭问题给出判断、概率与置信度，150–250ms、$0.10/M 输入、输出零费用；A2UI 1.0 让智能体不再只回一段文字，而是回一张由应用原生组件绘制的可交互界面，首个稳定版以 Apache 2.0 开源；AlphaGenome 2 把基因组预测从组织平均压进单个细胞类型与状态，识别变异能力接近翻倍。三者指向同一件事：AI 的交付物正在从「供人阅读的答案」，变成「可以判断、可以核对、可以触发的工作节点」。

② 中间三条是国产与入口的正面照面（#4–#6）。阿里官宣 Qwen4 / Qwen4-Max 预览版，代际升级 + 兼容 OpenAI / Anthropic 接口 + 多入口铺开；xAI 发布 Grok Bot 1.0，把 AI 做成能进 Slack、Teams 与会议的「团队成员」；腾讯元宝搜索正式上线、同日曝字节要给豆包造「中国版 Muse」超级大脑。Decision 1 改「输出什么」、A2UI 改「交付成什么样」、Grok Bot 改「待在哪里」、元宝搜索改「从哪儿进来」——今天所有大动作都在重排「人和 AI 的接口」，而不只是模型能力。

③ 收尾两条落到钱与产线（#7–#8）。Anthropic IPO 认购数倍超额、904 亿美元融资与新增 114 亿云承诺把算力账本再摊开一层（明确区分 11-11「启动路演」与今日「认购超额 + 新账本」两个不同阶段）；fal / Luma 补上「换角不重拍」与「对话内出图」，让视频生成第一次有了后期局部可改的能力。一个往上游算钱，一个往下游省工时。

一句话：昨天在比谁先把能力铺到所有人手边，今天在比谁能把结果直接交到人手边，而交付物越具体，越要把权限、口径与账本先写清楚。

今天最高分给到 #1 Google Gemini Decision 1（9.4 / P0）：分量不只在 150–250ms 与 $0.10/M 的经济性，更在它把「判断」从「生成」里整个拆出来成了一个新品类，并与同日 A2UI、AlphaGenome 2 一起，把行业竞争从「生成能力」正式推向「交付物形态」——是本期所有叙事的起点。

五条可以立刻执行的线索：① 把素材初筛 / 合规打标 / 多尺寸质检换成 Decision 1 式的批量判断 API（一次 1000 题、250ms、$0.10/M），但先用自家标注集测校准误差、别拿官方 92.2% 当验收线；② 用 A2UI 式交互卡片在 Web 内部工具试点「候选物料 + 参数 + 审批项」一屏确认，把「读完再搬」压成「点一下」，Android 完整 1.0 与企业侧 0.9.1 未齐前不铺全渠道；③ 拿 Qwen4-Max 试跑现有 OpenAI / Anthropic 格式脚本（日报流水线、批量切图校验），先按「思考 + 回答总量」重新核 max_tokens，别把双 11 折扣价写进长期预算；④ 把 AI 队友进协作渠道的权限按项目隔离——Grok Build 分享链接暴露内部资料就是反面教材，未定稿宣发物料不开全量文件权限；⑤ 用 fal / Luma 的换角能力对一条已定稿旧片做 A/B（整片重跑 vs 局部重生成），比成片一致性与工时，同时把「活动标准信息包」同步喂给主流 AI 搜索可抓取的官方页面，做白帽 AEO 巡检、明确不操纵模型输出的合规红线。
