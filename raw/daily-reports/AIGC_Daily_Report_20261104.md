## 一、AI 模型 & Agent

### #1 ⭐ 腾讯混元 Hy4 正式版发布：770B 首次引入视觉与电脑操作，首次跻身最强开源模型之列

> **来源**：[腾讯混元官网 Hy4](https://hy.tencent.com/research/hy4) · [人民网 / 网易转载](https://www.163.com/dy/article/LATH2TUF0530QRMB.html) · [腾讯科技](https://news.qq.com/rain/a/20261104A09IBJ00) · [21 世纪经济报道](https://www.163.com/dy/article/LATB83L105568W0A.html) | **评分**：9.4/10 | **标签**：模型发布 / 多模态 / 游戏引擎 / 办公协同

#### 核心事件
11 月 4 日，腾讯混元发布新一代大语言模型 **Hy4 正式版**，官方称随着模型能力再次全面跃升，**Hy 首次跻身最强开源模型之列**。相比 8 月的 Hy4 preview（770B 总参数 / 49B 激活 / 1M 上下文），正式版显著扩展了预训练和后训练规模，**首次引入视觉理解能力**，并大幅提升指令遵循、长文理解、长程 Agent、深度研究等综合能力；同时**首次支持电脑操作（Computer Use）**，可结合命令行与图形界面处理任务。模型权重将于近期开源并发布系统卡片，重点关注网络和生物安全风险；定价与 preview 持平，更省成本的 **Hy4 flash** 将于近期发布，下一代 **Hy5** 规模将进一步扩大。

#### 技术亮点 / 影响分析
- **视觉 + 工具链解锁真实生产力**：官方称 Hy4 通过感知、推理和工具调用，可做细粒度图像处理、复杂图表分析、数学视觉推理；针对 **Blender、CAD** 等专业软件和跨应用长程任务做了专项训练。卫星图定位、图表问答这类「看得懂才做得对」的任务被摆到台前。
- **和游戏引擎深度绑定**：与腾讯 **IEG 专业游戏开发者**合作优化数据与评测，重点提升功能实现、玩法逻辑、状态理解、资产处理，实现对 **UE、Unity、Godot** 的深度适配并开始扩展至多人联机开发；相比 preview，**GameDev +19.1%、GameLogic +9.8%**。前端侧也针对复杂交互、状态管理、前后端联动做了优化。
- **金融与办公是另两个主战场**：基于真实金融场景构建数千个工作空间、上万个高质量任务，联合腾讯金融科技组织 **213 位专家、579 个真实任务**众测，综合表现位居开源模型第一；已在 **WorkBuddy / CodeBuddy、元宝、企业微信智能助理大圆、ima、腾讯云 Tokenhub** 上线，借企业微信套件连通聊天、邮件、文档、日程与会议，多项目并行时能理清进展、识别待办与临近截止事项。
- **为 RSI 做准备**：官方称 Hy4 正积极为下一阶段递归自我改进做准备，结合 **Hyra 2.0** 优化了内部同架构小模型的预训练基础设施，自动训练出多项评测优于官方的 Jev 模型，并开源了单细胞表征基础模型 **HyCell** 与物理场基础模型 **HyPDE**。
- **需要保留的判断**：混元团队自己承认，尽管已是最强开源模型之一，**与顶尖闭源模型仍有较大差距**；「首次跻身」为官方自评口径，权重尚未实际开放，最终定位要看开源后的第三方复测。

#### 三句话总结
1. 腾讯混元 Hy4 正式版在 770B preview 基础上首次引入视觉理解与电脑操作，官宣首次跻身最强开源模型之列，权重近期开源、Hy4 flash 与 Hy5 已排上日程。
2. 它的差异化不在参数，而在**和腾讯 IEG 游戏开发者、企业微信办公套件、金融众测的深度 Co-Design**——UE / Unity / Godot 适配带来的 GameDev +19.1% 是最能说明问题的一个数字。
3. 对 CODM 宣发团队：这是本期**最该立刻开一条试点线**的条目——「视觉理解 + 电脑操作 + 游戏引擎适配」正好对应实机录屏理解、素材图表核对、Blender/CAD 资产处理三类高频活；建议按官方口径先挑**边界明确、结果易检查**的单任务（如一版卖点图的图表数据核对）验证，再评估接入现有生图流水线。

### #2 ⭐ 腾讯微信视觉团队开源 WeVisOne-VL：一个模型统一检测 / OCR / 分割 / 抠图，发丝级 Alpha 抠图

> **来源**：[GitHub Tencent/WeVisOne-VL](https://github.com/Tencent/WeVisOne-VL) · [技术报告 arXiv:2610.31329](https://arxiv.org/abs/2610.31329) · [机器之心 / 微信公号](http://mp.weixin.qq.com/s?__biz=MzI3MzE1NDA2Nw==&mid=2649896956&idx=1) · [人人都是产品经理](https://www.woshipm.com/ai/6488835.html) | **评分**：9.0/10 | **标签**：开源 / 视觉大一统 / Alpha 抠图 / 宣发工具

#### 核心事件
腾讯微信视觉团队开源视觉语言模型 **WeVisOne-VL**（2B / 4B 双版本），把**目标检测、指代定位、计数、指向、OCR、分割、抠图**七大类任务塞进同一个模型。思路是「大模型负责找、小解码器负责画」：物体级的框、点、文字全部作为结构化文本直接生成，像素级的蒙版与透明度交给一个仅 **9.6M 参数**的轻量像素解码器补完，**推理全程无需外挂 SAM**。权重、推理代码、评测流程、在线 Demo 全部开放，腾讯自研代码采用 **Apache 2.0** 协议。

#### 技术亮点 / 影响分析
- **架构很省**：以 Qwen3-VL 为底座，把所有任务统一为结构化 next-token 预测，坐标用专用 token 表示、一个坐标只占一个 token；每个预测框后跟一个特殊 token，其隐藏状态作为该物体的「特征摘要」，连同框位置与多层 ViT 特征喂给 9.6M 像素解码器直接画全分辨率蒙版或 Alpha 抠图。传统「检测模型 → SAM 分割 → 抠图模型」三段接力被收进一套模型体系。
- **数据底座**：知识图谱驱动的自动标注引擎累计标注超 **1 亿张图像**；顺手开源了 **Mask2Alpha 标注器**，能把粗糙二值蒙版转成高质量 alpha 抠图标注。
- **最贴业务的是「会说没有」**：目标不存在时老实返回 None。自建 **WeRef-Bench** 上 4B 版拒答率 **96.4%**（同级 Rex-Omni-3B 43.3%、Qwen3-VL-8B 18.3%，另有公开评测 Ref-ZOM 上 86.0%）；计数采用「先逐个框出、再报总数」，结果可逐项核对。
- **硬指标**：4B 在 30 余个基准全面领先所列 9B 以内开源对手——Dense200 密集检测 F1 **71.3**（最强基线 58.7）、PixMo-Count 计数准确率 **89.6%**（82.8%）；发丝级抠图上，文字指代抠图 MAD **9.8 对 22.4**、框提示 **7.3 对 15.4**，误差直接减半以上。
- **需要保留的判断**：官方成绩均为特定基准与贪心解码设置下的结果；第三方实测反馈在「细长结构（灯杆）」「一个物体看起来像两个（带缝隙的长沙发）」仍会出错，微调代码仍在 TODO。上生产前务必用自有素材复测。

#### 三句话总结
1. 微信视觉团队开源 WeVisOne-VL，用 4B 主模型 + 9.6M 像素解码器把检测、OCR、计数、分割、发丝级 Alpha 抠图收进一个入口，无需外挂 SAM，Apache 2.0 全量开放。
2. 真正的差异化不是刷分，而是 **96.4% 的缺失目标拒答率**——自动化流水线里「宁可说没有、也不乱框」比高 F1 更接近可用。
3. 对 CODM 宣发团队：这是本期**最容易直接落地**的一条——角色/武器/道具的**批量抠图与背景替换**、宣发长图里的**文字区域检测与 OCR 校对**、KV 素材的自动标注，三件事原本要串好几个模型；2B 版本可本地或边缘设备跑，建议先拿一批历史 KV 素材做抠图质量与小目标计数对比，重点验官方也承认的「细长结构」翻车场景。

### #3 ⭐ OpenAI 让 GPT-6 Astra 跨进物理世界：一周设计出 Codex 语音设备，与马自达合作汽车气动设计

> **来源**：[OpenAI 官网《Accelerating engineering for the physical world》](https://openai.com/index/accelerating-engineering-for-the-physical-world/)（11 月 3 日）· [IT之家 / 网易](https://www.163.com/dy/article/LATCS6GF0511B8LM.html) · [凤凰网科技 / 腾讯新闻](https://news.qq.com/rain/a/20261104A07KG000) | **评分**：9.2/10 | **标签**：工程设计 / Agent / 计算机辅助设计 / 制造业

#### 核心事件
11 月 3 日 OpenAI 发布研究文章，公布 **AI 辅助实体产品研发**进展：两名员工把 GPT-6 Astra 当作业余项目，在**不到一周**内完成一款可通过语音与 **Codex** 交互的便携设备设计，模型承担了外观造型、外壳与内部固定结构、电子元器件选型、**PCB 布局与连线**、用户界面、固件以及连接 Codex 的软件集成，全程工程师未直接手工修改模型生成的设计；代工厂随后在**不到一个月**内做出一小批实体原型机。同时宣布与**马自达**开展研究合作，用 AI 辅助汽车空气动力学与碰撞安全设计。

#### 技术亮点 / 影响分析
- **跨的是「数字 → 物理」这道门槛**：不再是写代码、做网页、生成图片，而是机械、电子、软件三类任务协同，输出能交付给代工厂的 CAD / PCB / 固件设计文件。演示里研究员对着设备问「我现在有正在运行的智能体吗」，设备答「有 5 个」。
- **新基准与内部模型**：在考察三维零件重建、装配体识别、电路板连接关系的 **BenchCAD 2.0** 上，OpenAI 披露一款较新的未命名内部模型平均得分 **0.875**，GPT-6 Astra 最高推理档为 **0.594**——官方称结果初步表明新一代模型有望提高专业工程设计迭代效率，但也明确说明基准分不等于真实制造任务成功率。
- **两条外部合作**：与马自达的空气动力学及碰撞安全工程师合作，让 Astra 生成不同车头几何造型并结合气流仿真评估方案，帮工程师判断哪些造型特征真正影响气动表现、哪些区域仍留有造型自由度；扩大与 **Chip Ganassi Racing** 车队合作，把零件 3D 扫描数据转成可编辑 CAD 与二维制造图纸，解决原始设计文件缺失的逆向建模耗时问题。
- **用量信号**：自今年 2 月以来，OpenAI 硬件团队使用 AI 模型消耗的 **Token 增长 23 倍**，Codex 与 ChatGPT 已用于计算机辅助设计、制造图纸生成、工程仿真及设计审查。
- **OpenAI 自己划的边界**：模型**未能始终正确考虑生产工艺限制、尺寸公差与装配细节**，投产前仍经历多轮人工审查与迭代；外部合作均处研究阶段，输出由工程师审核，尚无量产验证结果。

#### 三句话总结
1. OpenAI 展示 GPT-6 Astra 参与实体硬件设计：两人一周完成 Codex 语音设备全套机械 / PCB / 固件设计、代工厂一月出原型，并宣布与马自达合作汽车气动与碰撞安全仿真。
2. 分量不在「AI 画了张效果图」，而在它开始**同时处理机械结构、电气连接与软件集成并产出可交付文件**；但 0.875 vs 0.594 的 BenchCAD 差距与「公差、装配仍需人工返工」也如实标出了从设计到量产的鸿沟。
3. 对 CODM 宣发团队：短期用不上画 PCB，但**「生成多个候选方案 → 用仿真/规则快速评估 → 人工筛选」**这套范式可以直接搬到宣发物料——比如一次性出多版 KV 构图/角色姿态变体，用品牌规范与版式规则自动初筛，再交人工定稿；另外周边、展台、实体赠品的概念设计也可开始试水 AI 辅助建模。

### #4 ⭐ 苹果 2026 财年 10-K 首次警告：AI 智能体或「不可预测」行事，可能引发诉讼并损害声誉

> **来源**：[苹果 Form 10-K（2026 财年）](https://investor.apple.com/sec-filings) · [中国日报](https://ex.chinadaily.com.cn/exchange/partners/82/rss/channel/cn/columns/h72une/stories/WS6aea8bdae4b0e14252fc8fa4.html) · [CNBC / 财联社](http://mp.weixin.qq.com/s?__biz=Mzg4MTEyNzc4Mg==&mid=2247651733&idx=1) · 新浪财经 | **评分**：9.0/10 | **标签**：合规 / 风险披露 / 智能体 / 权限治理

#### 核心事件
11 月 3 日（美国时间周二），苹果在提交的 **2026 财年年度报告（Form 10-K）** 中新增风险因素，首次警告**第三方 AI 智能体**可能以「非预期或不可预测的方式」行事，使公司面临**诉讼风险并损害声誉**。文件写道：这类智能体可自主与内部或外部系统交互（某些情况下这些系统可能并未授权其访问）、执行或修改代码、发送通信、完成交易，且可能「采取未经指示、指导或授权的行动」；其中部分后果（如删除数据、完成交易）可能难以甚至无法撤销。

#### 技术亮点 / 影响分析
- **性质变了**：这不是发布会上的技术展望，而是**面向投资者的法律文件**。核心信号是——AI Agent 赛道已从概念进入实战，OpenAI 的 **Dots**、Meta 的 **Muse** 等能长时间自主跨应用执行任务的商用产品已落地，任何一起事故都会成为行业级负面新闻，而硬件入口方天然处在舆论与责任链的风口。
- **苹果自己承认「管不住」**：文件明确「公司对第三方 AI 智能体及相关技术的监督和控制能力**可能有限**」，并称围绕 AI 与「超级智能」的监管环境瞬息万变、难以预测，适应新法规可能需要大量成本。这被外界解读为提前在法律层面划清责任边界。

### #5 ⭐ Anthropic 开源 FlashProve：用 zkSNARK 给大模型办「防伪身份证」

> **来源**：[Anthropic 官方研究 Provable Inference](https://www.anthropic.com/research/provable-inference) · [机器之心 / 36 氪](https://36kr.com/p/4054648135930754) · X @AnthropicAI | **评分**：8.9/10 | **标签**：密码学 / 可核验来源 / 开源 / 模型供应链

#### 核心事件
Anthropic 开源 **FlashProve**——一套用 **zkSNARK**（零知识简洁非交互式论证）证明「AI 回复确实来自承诺的模型权重」的系统，被机器之心形容为给大模型办了一张「**防伪身份证**」。它解决的不是「回答对不对」，而是「**这句话到底是不是你指定的那个模型生成的**」：模型服务商交付给用户的，未来或许不再只有回答和 Token，还会多出一份不可篡改的密码学凭证。

#### 技术亮点 / 影响分析
- **从学术设想走进工程实操**：相比前代系统，生成证明速度**快了几个数量级**，让「可验证推理」首次具备工程讨论价值；覆盖合规监管、模型供应链安全，以及医疗诊断、金融决策、法律分析等对模型身份确认有硬要求的高价值场景。
- **代价仍然很实**：生成证明所需 GPU 时间仍比普通推理（vLLM）高约 **72–94 倍**，若每个请求实时生成证明，服务成本将明显增加。
- **支持范围有限**：当前实验针对**整数运算版本**的模型与 **Greedy Decoding（贪婪解码）**，浮点计算、随机采样等推理方式待扩展；上下文证明规模最多展示到 **1024 Token**，长上下文、大规模 Agent 工作流、复杂多轮交互如何高效生成与验证仍待解决。
- **最关键的一条边界**：FlashProve 证明的是**回答来自指定模型、推理过程完整**，**并不证明回答本身正确**——如果指定模型产生幻觉，证明依然会通过。它管的是身份与完整性，不是能力与事实准确性。
- **和昨天的连续剧**：本期 #7（11-03）报道过 Hugging Face 上「14 万亿参数 Anthropic 下一代模型」被社区扒皮为随机数伪造，结论是「这个行业最稀缺的不是算力，是**可核验的来源**」。FlashProve 正是把这句判断变成一行可运行的代码——从「靠扒」走向「靠证」。

#### 三句话总结
1. Anthropic 开源 FlashProve，用 zkSNARK 证明回复确实由承诺的模型权重生成，把「可验证推理」从学术设想推到工程实操，代码与研究已公开。
2. 它给出的是**身份与推理完整性的密码学凭证**，不是正确性保证；72–94 倍的 GPU 开销、整数运算 + 贪婪解码、1024 Token 上限，决定了短期内只会先用在高价值、强合规场景。
3. 对 CODM 宣发团队：把它和昨天的「14T 假权重」连起来读——**来源核验要前置到引用之前**。落到日常，是给外包/协作方交付的 AI 生成素材建立一套可追溯凭证（哪个模型、哪个版本、哪次生成、谁审核），既防「内部版/泄露版」模型混入，也为将来平台侧的 AI 标识与版权举证留底。

## 今日观察

八条新闻其实在讲同一个动作的两面：**给 AI 装上手脚，再给它上锁**。

**装手脚**这半边，今天密度罕见地高。混元 Hy4 第一次睁眼看图、动手操作电脑，还把 UE / Unity / Godot 啃进评测表；OpenAI 让 Astra 一周画出一台能语音对话 Codex 的实体设备、代工厂一月出样，又拉马自达一起用气流仿真挑车头；京东干脆把物理 AI 写成五年 300 万台机器人的采购单；微信 WeVisOne-VL 则把「看图 + 抠图」这件最费手的活压进 4B 模型 + 9.6M 解码器。共同点是——**交付物从「一段文本 / 一张图」变成了「一份可编辑、可交付、可进流水线的文件」**：CAD、PCB、Alpha 蒙版、原生工程。

**上锁**这半边同样没闲着。苹果把「智能体可能不可预测行事」第一次写进 10-K 的法律文本，还坦承自己管不住第三方智能体；Anthropic 用 FlashProve 给模型输出办密码学身份证，把昨天「14T 假权重」那句「最稀缺的是可核验来源」变成可运行的代码；CrowdStrike 摆出 AI 终止开关，Redwood 逐条拆 OpenAI 的对齐监控处置，OpenAI 自家 Alignment 团队承认评测与生产差 10.2–37.4 个百分点。**当 Agent 开始真的删数据、发通信、完成交易，权限边界、操作留痕与一键叫停就从工程细节升级成了合规底线。**
