### #1 ⭐ OpenAI 12 月起 ChatGPT 与 Codex 共享统一 Token 额度，Instant 聊天不计费

> **来源**：[OpenAI 官方支持文档](https://help.openai.com/) · [IT之家](https://www.ithome.com/) · 凤凰科技 · 新浪财经 | **评分**：9.2/10 | **标签**：产品与定价 / 订阅策略

#### 核心事件
10 月 31 日深夜至 11 月 1 日凌晨，OpenAI 官方支持页面上线新文档《理解 ChatGPT 与 Codex 使用限制》，宣布**从 12 月开始**，随着把 ChatGPT Work 的智能体能力并入 ChatGPT 主体验，**Plus、Pro、Business 三档订阅在 ChatGPT 与 Codex 之间共享同一份使用额度**。计费口径同时切换：不再按「几小时内能发多少条消息」计数，而是**统一按 Token 计量**，实际消耗速度取决于所选模型与任务复杂度。官方给了唯一的豁免——**Instant Chat（即时聊天）不占额度**，仍然无限量。

#### 技术亮点 / 影响分析
- **额度合池**：以前聊天和写代码是两笔账，现在是一笔。对重度 Codex 用户来说，这意味着「跟 ChatGPT 多聊几句」会直接吃掉编码预算，反之亦然。
- **按 Token 计价**：高级模型、复杂推理、长代码任务消耗更快。官方**尚未公布**各档位的 Token 总盘子与跨模型折算表，这也是社区质疑「是否变相缩水」的焦点。
- **耗尽后的三条路**：等待额度自动重置 / 升级到更贵档位 / 增购 Credits。官方承诺「绝大多数用户等待重置的频率不会高于此前」。
- **配套动作**：几乎同一时间 OpenAI 上线了「设备绑号上限」，一台设备绑定过多付费账号会被直接封锁。
- **背景**：此前一个月内 Codex Pro 额度刚经历「先降后恢复」的反复，加上 IPO 预期下的算力成本压力，这次合池被普遍解读为成本侧的必然动作。

#### 三句话总结
1. 12 月起 ChatGPT 与 Codex 共用一个 Token 池，Instant 聊天是唯一的无限量缺口。
2. 计费从「按条数」换成「按 Token」，重模型、长任务消耗更快，官方没公布折算表。
3. 对宣发团队：把 AI 当成「聊天 + 干活」两件事的预算模型要作废了——**同一份额度，聊得越多，干得越少**，需要重新排优先级，把额度留给真正出片的任务。

### #2 商汤开源 SenseNova Loop-9B-Preview：32 层权重跑出 56 层计算，9B 对标 27B

> **来源**：[商汤科技官方](https://www.sensetime.com/) · [Hugging Face `sensenova/SenseNova-Loop-9B-Preview`](https://huggingface.co/sensenova/SenseNova-Loop-9B-Preview) · 智东西 / 量子位 | **评分**：8.9/10 | **标签**：开源模型 / 架构创新

#### 核心事件
10 月 30 日晚，商汤开源日日新 **SenseNova Loop-9B-Preview**，权重与代码分别上 Hugging Face 与 GitHub，**Apache 2.0** 许可，可商用、可修改、可再分发。核心思路是 **Looped Transformer**：模型共 32 个独立解码器层，首尾各 4 层正常跑，中间第 4–27 层共 24 层**共享权重执行两遍**（写成 B(B(h))），一次前向完成约 **56 次层计算**，却只存 32 层权重。官方口径是「约 9B 参数媲美约 27B 参数量级」。

#### 技术亮点 / 影响分析
- **用时间换深度，不是用参数换深度**：总参数约 9B、推理时实际参与计算约 **14.6B**；训练上下文最长约 **262,144 token**（256K），文本 + 图像输入、文本输出。
- **mHC（流形约束超连接）**：为防第二遍循环把信号洗糊，用两条残差流 + Sinkhorn 归一化的可学习映射做路由与融合（迭代 20 次）；注意力每 4 层一组，3 层线性 + 1 层全注意力，循环边界对齐整组。
- **实测（厂商自报）**：对 Qwen3.5-27B，BIRD-Dev **71.38 : 69.84**、WorkBuddy Bench **66.89 : 60.53**、RaccoonPPT **70.70 : 59.08**、TeamBench **48.89 : 44.44** 均反超；但 Terminal Bench 2.1 **40.45 : 47.19**、T³-Banking **18.56 : 19.59** 两项落后。mHC 消融：GPQA Diamond **+4.42**、TeamBench **+13.34**。
- **代价要说清**：省的是显存里的参数，不是每个 token 的算力——56 次层计算照样跑，首 token 延迟更高、长文本吞吐吃亏；技术报告仍标 TBD，RaccoonPPTBench 是商汤自研评测集，成绩全为厂商自报。
- **部署门槛**：BF16 权重接近 18GB，24GB 显存（如 RTX 4090）可跑；加载需 `trust_remote_code=True`，官方仅在 Transformers 5.18.0 + PyTorch 2.11 + CUDA 13.0 验证过；社区已有 Q8_0 GGUF（约 8.9GB）。10 月 31 日登上 HF 趋势榜。

#### 三句话总结
1. 商汤把 24 层权重循环跑两遍，用 32 层存储换 56 层计算，9B 去够 27B，Apache 2.0 可商用。
2. 赢在办公、多步 Agent、复杂推理，输在超长链路终端操作；省显存但不省延迟，成绩全是厂商自报。
3. 对宣发团队：9B 权重 + 单张 24G 卡 = **本地私有部署的 PPT/文档/多步 Agent 流水线**第一次变得可负担，素材与脚本不出内网的方案可以排上日程。

### #3 DeepSeek 开源 Super-agent：Router + Worker 双层架构，任务耗时砍半

> **来源**：[DeepSeek Harness 团队技术文章](https://github.com/deepseek-ai/dsh-superagent-prototype) · GitHub 开源原型（MIT）· 智东西 / 潮新闻 | **评分**：8.8/10 | **标签**：Agent 架构 / 开源

#### 核心事件
10 月 31 日晚，DeepSeek Harness 团队发布《Super-agent 设计探索：迈向更自主的 Agent 系统》，并开源研究原型 **`dsh-superagent-prototype`**（MIT 协议，当晚接近 1095 star）。它不是新产品，而是一套把**调度与上下文同步从人手上移到系统层**的架构：目标是让 Agent 跨会话保持上下文、并行推进多任务、无人 @ 也能主动干活、长期在线异常自愈。

#### 技术亮点 / 影响分析
- **问题定义**：一个人通常只能同时跟进 **3–5 个活跃会话**——瓶颈已经不在模型，而在人的注意力。
- **Router 层**：常驻全局节点，统一接群聊 / GitHub / 邮件入口消息，**只分派不干活**（甚至可以不配 Bash 工具），用轻量模型即可；上一轮推理期间积压的事件会自动合并批处理，单次决定分摊推理时间从 **6.4 秒降到 1.6 秒**。
- **Worker 层**：各自独立上下文、挂完整工具、配最强模型，负责复现问题 / 代码审查 / 功能开发；Worker **不直接对人说话**，只向 Router 汇报，由 Router 统一回复。
- **订阅与直通**：Worker 创建后直接订阅对应 Thread，后续事件程序直通、不再绕 Router。实测取消直通后，Router 决策次数增加约 **30%**，缓存读取 token 从 2323 万涨到 3177 万（**+37%**）。
- **投机执行**：借鉴分支预测——有人反馈 Bug，Agent 先在后台复现、分析、找简单修复，确认有价值才提交，否则保持安静。
- **两级事件过滤**：程序规则做 Fast Path 先筛噪音，LLM 做 Slow Path 再判是否行动。
- **实测数据**：模拟 300 条消息 / 20 个工作请求环境，Super-agent 任务完成时间**中位数 12.4 分钟、95 分位 15.7 分钟**；传统单 Session + Subagent 方案的 95 分位是 **29.5 分钟**——**快了近一倍**，代价是 Token 消耗上升。
- **配套机制**：存算分离（执行在云端、状态存数据库、本地只留轻量 daemon，电脑关机任务不停）+ 外部 Watchdog 看门狗。

#### 三句话总结
1. DeepSeek 把 Agent 拆成「一个只分派的 Router + 多个只干活的 Worker」，并开源了 MIT 原型。
2. 多任务完成时间中位数 12.4 分钟 vs 传统方案 95 分位 29.5 分钟，代价是 Token 消耗明显上升。
3. 对宣发团队：这正是「日报流水线 / 竞品监控 / 素材批处理」该有的形态——**一个常驻调度入口 + 多个并行执行的活儿**，而不是每天手动开七八个会话窗口来回切。

### #4 OpenAI 融资目标砍 100 亿至 200 亿美元，估值从 1.4 万亿降到 1.25 万亿

> **来源**：[彭博](https://www.bloomberg.com/) · [金融时报](https://www.ft.com/) · TechCrunch · 财联社 / 中国基金报 | **评分**：9.3/10 | **标签**：资本与融资 / 行业变局

#### 核心事件
10 月 31 日，据 FT 与彭博援引知情人士：**OpenAI 把最新一轮融资目标从 300 亿美元下调至约 200 亿美元，削减 100 亿（降幅 33.3%）；对应估值目标从 1.4 万亿美元下调至 1.25 万亿美元，缩水 1500 亿（降幅约 10.7%）**。公司此前把这笔交易宣传为「明年 IPO 前最后一次入场机会」。更关键的是**结构变化**：OpenAI 已设定出资承诺截止日（周五），部分投资者缩减认购额度，**首次交割预计到位资金不足 200 亿**，后续还需靠面向高净值个人的零售配售补足。

#### 技术亮点 / 影响分析
- **为什么缩**：科技股集中抛售（纳斯达克 100 当日跌 3.5%、纳指跌 2.9%、较 10 月 6 日高点回撤约 7.8%、10 月创去年 3 月以来最差单月）+ 市场对 AI 支出规模与回报周期的担忧 + Anthropic 即将上市分流同一批机构资金。
- **谁在出钱**：阿联酋财团（含国有科技基金 **MGX**）预计为最大参与方，OpenAI 同时获得在该地区租赁新建算力的选择权；Founders Fund、Coatue、红杉、a16z 与软银计划跟投。目前已获约 **110 亿美元**承诺。
- **估值路径**：今年 3 月上一轮融资后估值 8520 亿美元 → 7 月后一度喊到 1.4 万亿 → 现在 1.25 万亿。
- **行业信号**：不是 AI 需求被下调，而是**风险定价被重校**。融资照做，但「少拿一点、价格低一点、交割稳一点」——从估值驱动转向资本纪律。
- **传导链条**：融资 → 资本开支 → 设备订单。头部 AI 公司开始讲资本纪律，产业链需要重新区分「确定性订单」和「估值预期订单」。

#### 三句话总结
1. OpenAI 融资目标砍 100 亿至 200 亿美元，估值从 1.4 万亿降到 1.25 万亿，首次交割预计还不足 200 亿。
2. 触发点是科技股抛售 + AI 支出回报担忧 + Anthropic 上市分流资金，本质是风险定价重校而非需求下调。
3. 对宣发团队：AI 工具厂商的**融资节奏会传导到产品定价与免费额度**（这次 ChatGPT/Codex 合池就是同一周发生的），明年做 AI 素材预算要预留涨价空间。

### #5 Anthropic IPO 招股披露近 9000 亿美元隐性债务，黑石只给投机级评级

> **来源**：[SEC EDGAR 注册文件](https://www.sec.gov/) · 彭博 · [新浪财经](https://finance.sina.com.cn/) · IT之家 | **评分**：9.1/10 | **标签**：资本与财报 / 基础设施

#### 核心事件
Anthropic 于 10 月 26 日向 SEC 提交 IPO 注册文件（有望成为人类史上最大 IPO，市场预期估值约 1.5 万亿美元）。彭博 10 月 31 日报道：**招股文件显示公司计划通过远期履约义务，在服务器、建筑与电力等领域投入近 9000 亿美元**——这一规模远超资产负债表上列示的负债。账面口径是负债 **1175 亿美元**、现金 **1120 亿美元**；真正的故事全在财务报表附注里。

#### 技术亮点 / 影响分析
- **表外义务拆解**：表外采购协议规模从去年 12 月到今年 6 月翻至四倍、预估达 **2656 亿美元**，多数绑定云托管与基础设施合作，期限最长 **20 年**；尚未起租的租约总额 **3210 亿美元**；其余算力安排（含租约与修订协议）远期支出 **2450 亿美元**；另有 **210 亿**短期合作项目、**8 亿**数据中心开发成本担保；7 月向 AMD 采购 GPU 及相关硬件超 **200 亿美元**。
- **为什么看不见**：公司正从「租算力」转向「自建数据中心」，德克萨斯大学会计学教授 Patrick Badolato 指出这让业绩与前几年不再可比；分析师 Ravi Gomatam 直言「无论能不能赚到收入，这些承诺款都必须支付」。
- **估值预期同步下调**：部分投资者讨论的上市估值已从约 2 万亿降到约 **1.5 万亿美元**。
- **评级预警**：黑石（刚参与一笔 630 亿美元 AI 算力设备融资交易）向投资者表示，预计 Anthropic IPO 后可能拿到 **BB 区间**信用评级——属投机级（俗称垃圾级）中的较高档。
- **风险提示（招股书自述）**：GPU 价格、未来电价、燃油附加费都可能波动，部分协议含可变成本，很难锁定最终金额；社区对数据中心耗水耗电的抵制、低成本开源模型的竞争，都可能让收入覆盖不了成本。

#### 三句话总结
1. Anthropic 招股书披露近 9000 亿美元远期履约义务，是账面负债（1175 亿）的近 8 倍，全在附注里。
2. 表外义务一年翻四倍到 2656 亿，最长绑定 20 年；黑石预计其 IPO 后只能拿到 BB 投机级评级。
3. 对宣发团队：AI 供应商的**账单压力最终会转嫁到 API 定价与订阅策略**，Claude 这条线（含 Max/Ultra 额度规则）接下来大概率还会有动作，选供应商时把「对方的算力承诺年限」也纳入评估。

### #6 Roblox 财报：AI 游戏突破 7 万款，9 月时长 Top 100 超 80% 用 AI 辅助开发
