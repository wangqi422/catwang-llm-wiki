### #1 ⭐ OpenAI 网络安全模型一次跑出 948 个 Linux 内核提权漏洞，API 成本约 121 万美元

> **来源**：[OpenAI 官网《A thousand fewer paths to root》](https://openai.com/index/a-thousand-fewer-paths-to-root) · [央广网](https://www.cnr.cn/tech/gstj/20261105/t20261105_527863073.shtml) · [IT之家](https://www.ithome.com/1/022/476.htm) · [财联社 / 腾讯新闻](https://news.qq.com/rain/a/20261105A03B5800) · [新浪财经](https://finance.sina.cn/tech/2026-11-05/detail-inixrqea8989981.d.html) | **评分**：9.5/10 | **标签**：安全 / Agent 流水线 / 漏洞挖掘 / 补丁生成

#### 核心事件
11 月 4 日，OpenAI 发布安全研究报告，用一款**尚未正式公布的网络安全模型**驱动一条端到端流水线，完成 Linux 内核漏洞的「发现 → 动态验证 → 可利用性评估 → 补丁生成 → 人工复核」。在 10 月中旬的一次完整运行中，系统先由 Scout 智能体筛出 **5034 个审计目标、约 280 万行代码**（约占内核 7%），12 小时内产出 **2308 个去重候选漏洞**；隔离虚拟机动态复现 **1724 个**（74.7%，仅 3.1% 属模型分析错误）；最终生成 **291 个信息泄露 PoC** 与 **1169 个本地提权利用程序**，经变体归并后统计为 **948 个独立 LPE 漏洞**。全流程消耗 **121.34 万美元** API 额度，平均每个 LPE 约 **1279 美元**，其中利用开发阶段占 77.59 万美元。

#### 技术亮点 / 影响分析
- **从演示变成可计量流水线**：五阶段全自动化，交付物包含根因分析、最小化崩溃 PoC、候选补丁与完整 exploit，直接交给安全研究员复核提交。相比 7 月 GPT-5.6 Sol 跑出的 166 个 LPE，三个月后在同一加固环境里多出 **5 倍以上**。
- **「新利用技术」是比数量更硬的信号**：智能体使用至少 **10 种全新漏洞利用技术**，已由第三方内核漏洞专家核验确认；测试在启用 SMEP / SMAP / KASLR / HARDENED_USERCOPY 的防护环境下完成，并另在 Google kernelCTF 加固环境拿到 25 个信息泄露 PoC + 21 个 LPE（112 小时、约 32,936 美元 API）。
- **补丁也在被生成，而且能反查人类**：初版补丁存在冗余、性能影响、偏离编码规范、未覆盖同类变体等问题，加约束迭代后质量改善，部分研究生成的补丁还发现了人类专家既有修复方案里的缺陷。10 天内已有 **61 个 LPE 在上游修复、43 个拿到暂存补丁、299 个在公开讨论或报告流程中**。
- **模型自主性本身在换代**：OpenAI 称移除额外技术指导层后，GPT-5.6 Cyber 表现仍优于采用复杂编排的 GPT-5.5 Cyber——传统依赖多层 agent 编排 + 人工指导的漏洞研究流程可能要重做。研究归属 **Patch the Planet / Daybreak** 安全计划，已与 Linux 维护者合作按社区建议优先上报。
- **需要保留的判断**：数字与成本均为 OpenAI 自报、受控研究环境结果；按漏洞赏金估算的「1890 万–6630 万美元价值」是推演不是收益；模型同样可用于攻击侧，官方明确提醒维护者需加快修复、用户及时打补丁，并点名沙箱、隔离、缩小攻击面与形式化验证。

#### 三句话总结
1. OpenAI 用未发布的网络安全模型跑通 Linux 内核漏洞全自动流水线，2308 候选 → 1724 复现 → 948 个独立本地提权漏洞，总 API 成本约 121.34 万美元、单个约 1279 美元。
2. 分量不在数量而在**可计量、可复核、可提交**：10 种经第三方核验的新利用技术、61 个已上游修复、补丁能反查人类方案，标志「模型找洞」从演示进入工业化阶段，攻防两侧的门槛同时被拉平。
3. 对 CODM 宣发团队：这条应直接转成**内部工具链的安全动作**——凡接入素材库、企微文档、投放后台的自建脚本/Agent，趁这波把依赖组件的补丁节奏、沙箱隔离与「能否一键停」盘一遍；同时也提醒，用 AI 生成的宣发落地页/小游戏若含自写前端逻辑，上线前必须过一轮依赖与权限审计，别让「一句话生成」把漏洞一起带上线。

### #2 ⭐ OpenAI 发布 ChatGPT Images 2.6：原生 GIF 动图 + 参考图复用，生图提速 50%

> **来源**：[OpenAI 官网《Introducing Images 2.6》](https://openai.com/index/introducing-images-2-6/) · [The Verge](https://www.theverge.com/ai-artificial-intelligence/1026474/openai-chatgpt-animated-gifs-images-2-6) · [新浪财经](https://finance.sina.com.cn/stock/estate/integration/2026-11-05/doc-inixruna5706490.shtml) · [开发者文档](https://developers.openai.com/api/docs/guides/image-generation) · [中关村在线](https://ai.zol.com.cn/1269/12691374.html) | **评分**：9.2/10 | **标签**：图像生成 / GIF / SVG / 参考图 / 宣发工具

#### 核心事件
11 月 4 日，OpenAI 在 ChatGPT、Codex 与 API 同步上线 **Images 2.6**。最直观的变化是**原生 GIF**：输入一句提示词或上传一张图，即可生成循环动图，支持调速、逐帧编辑、循环分享；同时新增**参考图保存**（自己、宠物、常用角色存一次反复调用）与 **SVG 矢量输出**。官方称生图速度较前代提升约 **50%**，ChatGPT + Codex + API 每周产出图像已超 **40 亿张**（9 月披露为 30 亿张）。全订阅档位、网页/桌面/移动端全球开放，价格与 2.5 版持平（图像输入每百万 token 8 美元、输出 30 美元、缓存输入 2 美元）。

#### 技术亮点 / 影响分析
- **开发者侧拆成两款模型**：`GPT-Image-2.6 Flare` 主打速度，quality=low 时最快约 **6 秒**出图，并优化海报、产品图等含文字场景的排版；`GPT-Image-2.6 Sunburst` 主打中高画质细节与**多轮编辑一致性**。第三方 DesignArena 称 Sunburst 登顶 Image Arena 总榜，Flare 相对上代约快 2.6×（第三方自报，需自行复测）。
- **新增三个可控维度**：图片标注（image markup）圈选指定修改区域进入 API；`complexity` 参数控制模型「动笔前规划多少」，与管精细度的 `quality` 正交，官方建议局部编辑先从 low 起；GIF 走 `output_format: "gif"`，可控 `frame_count`（2–64）与 `frame_duration_ms`（20–2000），宽高需为 16 的倍数、画幅比 1:3–3:1，受总像素预算约束。
- **GIF 的做法是「精灵图拆帧」**：先画一张把连续动作分格排布的大图，再按序拼成循环，因此它同时考验单帧质量与**跨帧的角色/物体一致性**。官方点名的场景几乎全是社媒：品牌吉祥物动画、反应梗图、角色分镜试动作、静态商品图转循环广告。
- **实测边界要认清**：第三方实测显示帧数与画幅不总按提示词交付（要求 16 帧 4:3 实际给 12 帧方图）、背景与手部等细节会逐帧漂移、伞柄/持物关系易出错；**编辑接口目前不支持直接输出 GIF 与 SVG**；静态 SVG 不等于分层 PSD。真人脸、商标、品牌资产进动图前要单独过合规。
- **和昨天主线的呼应**：昨日 #7 普林斯顿空间智能给出「换视角后最强模型仅 39.7%」的冷水，今天 Images 2.6 用「参考图锁定 + 多轮一致性」在工程层面绕开一部分三维一致性问题——**不靠模型理解世界，靠把角色固定成可复用参考**。

#### 三句话总结
1. OpenAI 上线 Images 2.6，ChatGPT 首次原生支持 GIF 动图与参考图复用，出图提速约 50%，API 拆出 Flare / Sunburst 两款模型并新增 SVG、圈选编辑与 complexity 参数，价格不变。
2. 它把「静图 → 动图 → 矢量可改」压进一个入口，交付物从一张图变成**可直接进社媒与设交流水线的循环素材**；但帧数/画幅不完全听话、跨帧细节漂移、编辑接口不支持 GIF/SVG，都是上生产前必须实测的边界。
3. 对 CODM 宣发团队：这是本期**最容易当天就试**的一条——表情包/梗图、角色动作试帧、商品与周边循环广告、Logo 与图标的 SVG 底稿，四类高频活可以一次串起来。建议先拿一版现有角色立绘存成参考图，跑「同角色 3 个动作 GIF」比对跨帧一致性，重点验官方也承认的帧数与持物关系；真人脸、武器商标与品牌资产仍走人工终审。

### #3 ⭐ 甲骨文迫于美方施压取消与腾讯 70 亿美元 AI 芯片租约，涉东南亚 10 万枚芯片

> **来源**：[金融时报（联合早报转述）](https://www.zaobao.com.sg/news/china/story20261104-9945155) · [路透 / Yahoo 财经](https://hk.finance.yahoo.com/news/) · [BlockBeats](https://www.theblockbeats.info/flash/375466) · [财经日报](https://news.jkn.co.kr/editions/chinese/post/1071480) | **评分**：9.0/10 | **标签**：算力管制 / 地缘 / 海外租赁 / 供应链

#### 核心事件
11 月 4 日，《金融时报》援引知情人士报道：**甲骨文（Oracle）在特朗普政府施压下，取消了与腾讯一份价值约 70 亿美元、为期五年的 AI 芯片租赁合同**。该合同 10 月 1 日首度被披露，内容为通过甲骨文在**东南亚多个数据中心**向腾讯提供最多 **10 万枚先进 AI 芯片**的远程算力，用于大模型训练与智能体工具研发，腾讯需预付 30% 租金，是其迄今规模最大的海外算力租约。美国官员主动接触甲骨文表达「强烈关切」后交易取消；同时广东省高级官员亦曾到访腾讯，要求支持国产芯片。甲骨文、腾讯与美国政府均未发表官方声明。

#### 技术亮点 / 影响分析
- **管制的落点从「芯片清单」移到「合同层」**：美国出口管制限制的是先进芯片进入中国，但中国企业远程租用部署在海外的算力此前并未被全面禁止。这次没有新规出台，仅凭官员「表达关切」就让一份已签合同作废——**合规压力被前置到了交易签署之前**。
- **双向挤压**：美方警惕中企经海外数据中心获取尖端算力，中方则要求降低对美系芯片依赖，形成双重压力。腾讯 2026 年 Q2 资本开支 **527.84 亿元**（同比 +176%、环比 +65%，单季历史新高），上半年 847.2 亿元已超 2025 全年 792 亿元，算力需求的确定性被直接动摇。
- **同期配套信号**：英伟达被曝要求海外云服务客户自新合同起至少 **51% 服务面向非中国客户**（目前仍为非强制指导）；阿里、腾讯、字节大量订购 RTX Pro 5500 工作站卡，但有报道称 4 个月内仅能供货约 1%。低规格卡的争夺也在升温。
- **对行业的含义**：算力采购的评估维度里要加上一条「**这笔交易会不会被政治叫停**」。海外租约、跨境云、第三方托管都得留备选路径；对国产算力栈（昇腾等）的适配从「可选项」变成「连续性保障」。
- **需要保留的判断**：报道基于匿名知情人士，合同取消原因、是否有替代方案、腾讯算力缺口如何补均未获官方确认；金额与芯片数量为 FT 口径。

#### 三句话总结
1. 甲骨文在美方施压下取消与腾讯约 70 亿美元、五年期、涉东南亚 10 万枚先进 AI 芯片的租约，该合同 10 月 1 日才首度披露，是腾讯最大一笔海外算力租约。
2. 关键变化不是钱或芯片，而是**管制从出口清单延伸到海外租赁交易本身**——规则没改，但合规压力已前置到合同层，叠加英伟达 51% 指导与国产化要求，算力供应的确定性被重新定价。
3. 对 CODM 宣发团队：这条离日常执行较远，但直接影响**生图/生视频 API 的容量与价格预期**——集中投放期不要把所有批量生成任务压在单一海外推理供应商上；沿用「单条素材 token/算力成本」这一固定口径做预算，并保留一家国产/本地备选，避免供应商侧突发调整打乱排期。

### #4 ⭐ 世界模型扎堆乌镇：魔芯 MoWorld 2.0 昇腾原生 4D、百度 Apollo World、小米 WorldCast

> **来源**：[中国经济网](https://www.ce.cn/cysc/newmain/yc/jsxw/202611/t20261104_3283464.shtml) · [新华网浙江](https://www.zj.news.cn/20261104/d6b2d3a7e9b445e28e4e13f929828a7d/c.html) · [IT之家](https://www.163.com/dy/article/LATVI0F60511B8LM.html) · 魔芯科技公众号 · 百度 / 小米官方 X | **评分**：8.8/10 | **标签**：世界模型 / 4D 高斯资产 / 国产算力 / 分镜预演

#### 核心事件

### #7 编码模型「小而快」：Cognition SWE-2 Flash 与 Ricursive Ripple-65B 同日发布

#### 技术亮点 / 影响分析
- **Cognition 的关键动作是「RL 之前插中训练」**：先用高质量留出编码集 + token 效率曲线筛数据配方，收敛到数万亿 token 的科技文章/博客/代码混合，分三段训练、把最稀缺高价值数据放最后，再进 RL。能力不是换更大模型，而是把通才做定向进修——五分之一成本拿八成能力。
- **权重策略出现分叉**：Ripple-65B 直接 Apache 2.0 全放；Cognition 反而**不公开权重**，理由是训练中强化了网络安全能力（ExploitBench 从 11.3% 提到 34.8%），攻击侧同样可用，改为面向可信产业伙伴与实验室的「定向分享」。同一天 Kimi K3.1 Pro 也按 10-24 的承诺放出了 2.8T 权重（BF16 约 5.6TB，属已公告排期兑现，本期不单列）。

- **适用边界**：优势在标准代码智能体任务（代码评审、功能迭代、文档维护、终端运维、CI 工单），超长仓库重构、跨项目月级工程仍低于旗舰；Ripple-65B 的完整模型卡、量化版本与工具调用协议也仍待补齐。

#### 三句话总结
1. Cognition 用「中训练 + RL」把 276B 的 SWE-2 Flash 做到 1/5 价格、3 倍速度、Terminal-Bench 4.0 从 0.9%→20.0%；Ricursive 则开源 65B 稠密的 Ripple-65B，官方自报 Terminal-Bench 2.1 达 80.5、训练成本约 3200 万美元。
2. 两条路线共同说明编码模型的竞争正从「参数规模」转向「后训练配方 + 单位成本」，而权重开放策略反而分化——一家全放、一家因安全能力收紧为定向分享。
3. 对 CODM 宣发团队：不必追新模型，但可以借这个思路给**内部自动化脚本/批处理工具**做一次成本复盘——把批量改图、素材重命名、报表整理这类高频小任务换成低成本模型跑，先用自有 3 个中等难度任务记「一次通过率 + 端到端耗时」再决定是否切换；厂商自评分数一律不当验收依据。
