### #1 ⭐ Google 发布 Gemini Decision 1 与 Gemini Decisions API：不逐 token 生成，单次前向传播评 1000 题，150–250ms / $0.10 每百万输入

> **来源**：[Google 官方博客 / Gemini Decisions API](https://ai.google.dev/) · [Sundar Pichai 官方 X](https://aihot.news/) · [AI前线·9 项测试 7 项第一（网易转载）](https://www.163.com/dy/article/LBGN88CA05566ZHB.html) · [前瞻全球产业早报](https://t.qianzhan.com/caijing/detail/261112-ec9b81a7.html) · [8点1氪（腾讯新闻）](https://news.qq.com/rain/a/20261112A03KIG00) · [aihot.news 热度榜](https://aihot.news/) | **评分**：9.4/10 | **标签**：决策模型 / 新品类 / 低延迟 / 低成本 / 多模态

#### 核心事件
北京时间 11 月 12 日凌晨（当地时间 11 月 11 日），**Google 在 Google AI Studio 正式推出 Gemini Decisions API，由全新的 Gemini Decision 1 模型驱动**。与传统生成式大模型逐 token 生成文字不同，这款模型专为**封闭选项集里的决策任务**设计：它不解码答案，而是通过**单次前向传播**对预先设定的候选答案进行评分，直接返回判断结果、概率与置信度。官方口径下，它可在 **150–250ms 端到端延迟**内，对文本、图像、音频、视频与 PDF（最多 256K tokens）一次性评估**最多 1000 个是 / 否判断、多选（最多 255 个选项）或基于评分标准的打分题**。定价为**每百万输入 token $0.10、输出 token 费用为零**，约为 Flash-Lite 的五分之一。Google CEO Sundar Pichai 在 X 发文介绍，并展示了 Stitch Rapid 在几秒内设计完整产品流程的演示（1 倍速播放）；模型已上线 OpenRouter，Artificial Analysis 的 Decision Index 给出 66 分，中文媒体口径为「9 项测试拿下 7 项第一、准确率最高 92.2%」。

#### 技术亮点 / 影响分析
- **把"判断"从"生成"里拆出来，是一个新品类**：过去想让 AI 判断一封邮件是不是垃圾邮件、或决定一项任务该交给哪个 Agent，往往要调用生成式大模型、再从生成的文本里把结果抽出来。Decision 1 省掉整套文本解码，只做分类、评分与选择——对本来就只需要一个结果的任务，这是结构性省成本。
- **延迟与成本是硬指标**：150–250ms、一次 1000 问、$0.10/M 输入、0 输出费、1/5 Flash-Lite；官方同时称在多项基准上领先且校准误差最低。这让它更像一个"可批量调用的分类器接口"，而不是又一个聊天模型。
- **与 #2 A2UI、#3 AlphaGenome 2 是同一天的同构动作**：Google 没有再堆一个"更能生成"的通用旗舰，而是把输出形态拆成判断（Decision 1）、界面（A2UI）、单细胞预测（AlphaGenome 2）三个专用形态——竞争口径正从"会不会答"转向"能不能交付一个可直接用的结果"。
- **边界**：9 项 7 第一、92.2%、66 分多为 Google 官方或第三方单一口径，尚无统一独立复测；它专为封闭选项集任务设计，**不能生成开放式内容**，也不替代 Gemini 4 Argon / Carbon；"校准误差最低"为官方说法。

#### 三句话总结
1. Google 于 11-11 推出 Gemini Decisions API 与 Gemini Decision 1 决策模型，不逐 token 生成、单次前向传播对最多 1000 个封闭问题给出判断 / 概率 / 置信度，150–250ms、每百万输入 $0.10、输出零费用，已上线 OpenRouter。
2. 它把分类、评分、路由这类"只要一个结果"的任务从生成式模型里剥离出来，与同日 A2UI、AlphaGenome 2 一起，把行业竞争从"生成能力"推向"交付物形态"。
3. **对 CODM 宣发团队**：素材初筛、合规打标、多尺寸衍生质检这类"是 / 否 + 打分"的批量判断正是它最擅长的场景——过去用旗舰模型逐条读文本再抽结果，现在可换成一次 API 调用跑 1000 个问题、$0.10/M、250ms，适合给一版 KV 的几十个尺寸做批量合规与视觉一致性打分；上线前先拿自家真实标注集测一次校准误差，别直接拿官方 92.2% 当验收线。

### #2 ⭐ Google 开源 A2UI 1.0 生成式 UI 协议首个稳定版：智能体直接回复原生交互界面，Apache 2.0，Atlassian / Alation / 字节已接入

> **来源**：[Google 官方博客](https://developers.googleblog.com/) · [A2UI 官网](https://a2ui.org/) · [CopilotKit 1.0 发布说明](https://www.copilotkit.ai/) · [凤凰网科技·字节已提前布局](https://original.ifeng.com/c/8xytKFJnGvS) · [IT之家](https://www.ithome.com/1/025/862.htm) · [腾讯新闻·入口标准](https://news.qq.com/rain/a/20261112A03EH000) | **评分**：9.1/10 | **标签**：生成式 UI / 开放协议 / 原生渲染 / 智能体交付物 / Apache 2.0

#### 核心事件
北京时间 11 月 12 日（当地时间 11 月 11 日），**Google 宣布生成式 UI 开放协议 A2UI 1.0 正式上线**，官网已将 v1.0 列为现行版本（首个稳定版，v0.9.1 为上一版）。A2UI 是 Google 于 2025 年底公布的一份协议，让智能体不只回复文字，而是发送**声明式组件描述**、由客户端应用用自己的原生组件绘制交互界面——确认表单、图表、选择器都成为新的"回答方式"。项目以 **Apache 2.0 开源**，由 Google 创建、CopilotKit 与开源社区贡献。1.0 新增**双向函数调用**（`callAgentFunction` / `callRendererFunction`，航班或预约选择器可在组件内就地核查余位）、无障碍支持（ARIA live region / hidden）、扩展元数据命名空间、`allowedParents` / `allowedChildren` 嵌套约束、分级 `ValidationResult`（错误 / 警告 / 提示）、`requiresUserActivation`（如 `openUrl` 需真实用户操作）、多目录 `catalogId` 混合与 `@path` 动态数据绑定。开源渲染器覆盖 Web（React / Angular / Lit 稳定）、Flutter（移动 / Web / 桌面）、SwiftUI（iOS）、Jetpack Compose（Android，v1.0 仍为 Planned）；Web 与 Flutter 渲染器可在 MCP Apps 内工作。智能体 SDK 在 Python 之外新增 TypeScript 与 Dart。落地案例包括 **Atlassian 把 A2UI 引入 Jira**（工作项内用交互卡片向团队补问）、**Alation 用其构建指标卡与图表信息流**（可展示背后 SQL）、彭博社，以及**字节跳动早在 2026 年 6 月就为跨端框架 Lynx 发布 A2UI 渲染器**（Lynx GenUI Playground）；CopilotKit 同步推出基于 1.0 的 Generative UI（标准目录 70 组件，含 18 个 A2UI 基础组件）。

#### 技术亮点 / 影响分析
- **安全分工前置是它最值得抄的一点**：智能体只描述"要展示什么"，应用用自己的原生组件渲染；数据与子组件在服务端绑定，敏感数值不进入模型；采用**声明式数据格式而非可执行代码**，从根上避开让模型现场写 React / SwiftUI 带来的脚本注入、样式破坏与依赖冲突。组件目录（Catalog）提前收窄可选范围，参数还要过 Schema 校验。
- **它不是 MCP / AG-UI / A2A 的替代品，而是补上 UI 载荷这一层**：一条任务链可以是——智能体通过 MCP 取库存、通过 A2A 与另一个智能体协作、通过 AG-UI 把状态同步给前端、再用 A2UI 描述一张确认卡。与 MCP Apps（服务端预制 HTML + 沙盒 iframe）是两条路线：后者交付完整独立界面，前者强调跨端、动态组合与宿主体验一致。
- **交付物从"答案"变成"工作节点"**：纯文本智能体容易把"回答看起来正确"当终点，但企业任务真正闭环还差"让用户看懂状态、补齐信息、明确确认"三个动作。A2UI 把这三步做进界面，智能体竞争从答案正确率转向**任务完成率**。
- **边界**：版本状态并不整齐——Compose 的 1.0 支持为 Planned、Flutter / SwiftUI 仍 Alpha、Gemini Enterprise 当前注册仍走 0.9.1、ADK Web 集成 v0.8；准确说法是"协议核心进入稳定、生态拿到迁移基准"，不是全生态同步升级。官方 / 合作方案例均未给出统一的任务完成率、误操作率与大规模对照数据。

#### 三句话总结
1. Google 于 11-11 发布 A2UI 1.0 生成式 UI 协议首个稳定版，Apache 2.0 开源，让智能体以声明式消息回一张由应用原生组件渲染的交互界面，新增双向函数调用、无障碍与分级校验，Atlassian / Alation / 彭博 / 字节 Lynx 已接入。
2. 它以"模型描述、应用渲染、服务端管数据"的分工把安全边界前置，并与 MCP / A2A / AG-UI 互补，推动智能体交付物从供人阅读的答案变成可核对、可补充、可触发的工作节点。
3. **对 CODM 宣发团队**：「一版 KV 多尺寸 / 多语言 / 多渠道适配」最烦的就是把方案编号复制到另一个页面再确认——这类交互卡片能让 AI 把候选物料、参数与审批项直接渲染成可点选的确认单，把"读完再搬"压成"在界面里点一下"；但 Android 完整 1.0 与企业侧 0.9.1 尚未齐，建议先在 Web 内部工具做小范围试点，别一步铺到全渠道。

### #3 ⭐ Google DeepMind 发布 AlphaGenome 2：从组织平均深入单细胞类型，1.07 亿单细胞图谱 / 68 组织，识别变异能力近翻倍

> **来源**：[Google DeepMind 官方博客](https://deepmind.google/) · [智通财经·腾讯新闻](https://news.qq.com/rain/a/20261112A03YB200) · [前瞻全球产业早报](https://t.qianzhan.com/caijing/detail/261112-ec9b81a7.html) · [AI HOT 聚合池](https://aihot.news/) | **评分**：8.9/10 | **标签**：基因组 AI / 单细胞 / 条件架构 / 科学落地 / 预测引擎

#### 核心事件
当地时间 11 月 11 日，**Google DeepMind 发布新一代基因组 AI 模型 AlphaGenome 2**，能够预测 DNA 序列及其变异对**特定人类细胞类型和细胞状态**的影响。新模型采用**条件模型架构**，使用超过 **1.07 亿个人类和小鼠单细胞图谱、覆盖 68 种组织**训练，识别基因表达相关遗传变异的能力**接近上一代两倍**，并新增 DNA 甲基化等分子指标预测，支持在不重新训练的情况下分析此前未见过的细胞类型与生物状态。DeepMind 在博客中称，通过"从广泛的组织平均值深入到单个细胞类型和细胞状态，并重新设计模型架构，AlphaGenome 2 在变异预测性能上实现了阶跃式提升"，能把静态细胞图谱转化为**遗传学的预测引擎**——例如解析特定心肌细胞或血液免疫细胞内的活动，帮助发现仅在特定细胞类型中起作用的关键 DNA 变异。官方援引一项近期研究称，调控开关通过在肠道免疫细胞中过度激活 ETS2 基因驱动炎症性肠病，而 AlphaGenome 2 能在**计算层面复现这一发现**。目前模型通过 AlphaGenome API 开放非商业研究使用，并以私人预览版形式开放给商业研究。

#### 技术亮点 / 影响分析
- **从"平均"到"条件"，是能力而非参数量的跃迁**：上一代依赖组织平均值，会漏掉疾病相关细胞中的变异效应；条件架构让同一段 DNA 在不同细胞状态下被差异读取，且能外推到训练时未见过的细胞类型——这意味着它不只是拟合，而是学到了可迁移的调控规律。
- **有落地验证，不是纯跑分**：在计算层面复现 ETS2 / 炎症性肠病的已知发现，是"预测能对齐实验结论"的证据；对 AI 制药与疾病机理研究而言，这是可直接进工作流的工具类模型。
- **与 #1 / #2 同构**：同一天 Google 把"模型该输出什么"从通用文本，拆到判断（Decision 1）、界面（A2UI）、单细胞预测（AlphaGenome 2）三个专用形态——前沿实验室正从"一个模型包打天下"转向"按交付物形态做专用模型"。
- **边界**："接近翻倍"为官方口径，尚无独立大规模复测；当前仅非商业研究 API + 商业私人预览，未全面开放；与临床转化之间仍隔实验验证与监管。

#### 三句话总结
1. Google DeepMind 于 11-11 发布 AlphaGenome 2，用 1.07 亿单细胞图谱 / 68 组织的条件架构把基因组预测从组织平均推进到单细胞类型与状态，识别基因表达变异能力接近前代两倍，并新增甲基化等分子指标预测。
2. 它在计算层面复现了 ETS2 / 炎症性肠病的已知发现，说明能力已能对齐实验结论；与同日 Decision 1、A2UI 一起，体现"按交付物形态做专用模型"的路线转向。
3. **对 CODM 宣发团队**：直接业务关联弱，但"从平均人群拆到细分状态"的思路有迁移价值——别再拿一张"泛用户通投"物料打全场，用数据把玩家拆成更细的状态 / 圈层再给差异化内容；此外这类"专业领域 + 有条件预测"的模型，也是评估国产垂类模型能否进垂直工作流的一个参照系。

3. **对 CODM 宣发团队**：这是今天离宣发产线最近的一条——**「换角不重拍 / 同一镜头增删角色」直接对应"一版 TVC 出多地区版本、换皮肤角色、替换联动 IP"的需求**；建议拿一条已定稿的旧片做 A/B：原流程整片重跑 vs 换角局部重生成，比成片一致性与工时，再决定是否进正式管线；同时先核清商用授权与水印口径。

## 编辑点评

八条其实在讲同一件事：**从会答，到会判、会交、会干活**。昨天（11-11 期）比的是「谁能把能力最快最广地铺开」，今天比的换成了「AI 到底该交出什么」——最密集的动作来自 Google 一家，它没再发一个「更能生成」的通用模型，而是把输出形态拆成了判断、界面、单细胞预测三份。今天没有谁在比谁写得多，大家比的是谁交得出东西。

**① 上半场是「不生成」三连（#1–#3）**：Gemini Decision 1 不逐 token 生成文字、单次前向传播评 1000 题（150–250ms / $0.10/M 输入 / 输出零费用）；A2UI 1.0 让智能体回一张由应用原生组件绘制的交互界面而非一段文字（首个稳定版 / Apache 2.0 开源）；AlphaGenome 2 把基因组预测从组织平均压进单细胞类型（1.07 亿图谱 / 68 组织 / 识别变异近翻倍）。三者指向同一件事：AI 的交付物正从「供人阅读的答案」变成「可以判断、可以核对、可以触发的工作节点」。

**② 中间三条是国产与入口的正面照面（#4–#6）**：阿里 Qwen4 / Qwen4-Max 预览版代际升级 + 兼容 OpenAI / Anthropic 接口、xAI Grok Bot 1.0 把 AI 做成能进 Slack / Teams / 会议的团队成员、腾讯元宝搜索上线并曝字节给豆包造「中国版 Muse」。Decision 1 改「输出什么」、A2UI 改「交付成什么样」、Grok Bot 改「待在哪里」、元宝搜索改「从哪儿进来」——今天所有大动作都在重排「人和 AI 的接口」，而不只是模型能力。

**③ 收尾两条落到钱与产线（#7–#8）**：Anthropic IPO 认购数倍超额、904 亿融资与新增 114 亿云承诺把算力账本再摊开一层（明确区分 11-11「启动路演」与今日「认购超额 + 新账本」两个不同阶段）；fal / Luma 补上「换角不重拍」与「对话内出图」，让视频生成第一次有了后期局部可改的能力。一个往上游算钱，一个往下游省工时。

一句话：**今天不比谁写得多，比谁交得出东西，交付物越具体，越要把权限、口径与账本先写清楚**。
