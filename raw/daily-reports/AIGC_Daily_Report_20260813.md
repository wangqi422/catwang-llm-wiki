### #1 ⭐ DeepSeek V4 Pro 正式版深夜上线，DeepSWE 从 7.3 飙到 62.7 逼近 Fable 5

> **来源**：DeepSeek 官方 / 科创板日报 | **评分**：9.2/10 | **标签**：`模型发布` `Agent` `中国AI`

#### 核心事件

北京时间 8 月 13 日凌晨，DeepSeek 官网 API 文档悄然更新，模型版本从 V4-Pro 预览版切换至正式版 **DeepSeek-V4-Pro-0813**，调用模型名不变，API 与 Chat 端同步完成更新。新版本大幅增强 Agent 能力，支持 1M 上下文、最高 384K Token 输出，并兼容 Responses API、Codex 接入以及 OpenAI / Anthropic 双格式。最亮眼的是智能体编程基准 **DeepSWE 从预览版的 7.3 跃升至 62.7**，直接反超 Claude Opus 4.8，多项 Agent 评测逼近甚至反超当前公认最强的 Claude Fable 5。

#### 技术亮点 / 影响分析

- **「Agent 优先」的迭代逻辑**：DeepSWE（12.8→62.7）、Terminal Bench（72.1→87.9，逼近 Fable 5 的 88.0）涨幅最大，说明 DeepSeek 把竞争筹码继续押向 Agent 与编程场景，而非单纯聊天跑分
- **1M 上下文 + 384K 输出**：单次调用承载能力对标长代码库分析、大规模文档处理、多步骤 Agent 连续执行，直击长时任务痛点
- **价格暂未上调但已预告涨价**：当前 deepseek-v4-pro 定价为缓存命中 0.025 元 / 未命中 3 元 / 输出 6 元（每百万 Token），官网已明确「计划近期整体上调定价、涨幅较大」，能力提升与商业变现的节奏同步收紧

#### 三句话总结

1. DeepSeek V4 Pro 正式版（0813）凌晨上线，DeepSWE 从 7.3 飙到 62.7，多项 Agent 评测逼近 Fable 5，逼近开源模型的能力天花板
2. 1M 上下文 + 384K 输出 + Codex 接入，DeepSeek 明确押注「长时任务 Agent」赛道，与 Grok 4.6 同日正面交锋
3. 对 CODM 宣发团队：V4 Pro 的高性价比 Agent 能力适合承载批量素材分析、竞品情报归纳等重活，但 API 即将涨价，宜赶在调价前锁定高频任务的技术方案

### #2 ⭐ Grok 4.6 发布：主打长时任务 Agent，多基准登顶与 GPT-5.6 Sol 持平

> **来源**：xAI 官方 / IT之家 | **评分**：9.0/10 | **标签**：`模型发布` `Agent` `前沿竞赛`

#### 核心事件

北京时间 8 月 12 日晚间，SpaceXAI（xAI）正式发布 Grok 4.6，在 Grok 4.5 基础上重点强化长时间运行的智能体任务与复杂交互、视觉工作。新模型在 Artificial Analysis Intelligence Index 上以 61 分与 GPT-5.6 Sol 持平；CursorBench 3.2 达 69.9%、DeepSWE 1.1 达 65.9%，全面超越 Grok 4.5，在 GDPVal-AA v2、Harvey 法律智能体基准等多项测试登顶。目前已同步上线 Cursor、Grok Build、API，并接入 OpenRouter、Vercel、Cloudflare，首周提供 2 倍额度。

#### 技术亮点 / 影响分析

- **训练思路从「解难题」转向「做长活」**：补充训练引入 Agentic RL，覆盖知识工作、通用编程、内核优化、Web 开发、CAD 等真实多步任务环境，目标是让模型在数百步任务中持续稳定工作
- **「自我测试」能力是隐性亮点**：在更长任务链中会主动检查已完成工作、验证结果后再继续，首轮视觉与交互产出质量较 4.5 明显提升——这是 Agent 是否「省心」的决定性因素
- **激进的分发策略**：发布即多平台上线，API 定价 $2/M 输入、$6/M 输出（快速版翻倍），两周内从 4.5 迭代到 4.6，xAI 的发布节奏与生态铺开速度都在施压对手

#### 三句话总结

1. Grok 4.6 发布，主打长时任务 Agent，Artificial Analysis 综合指数 61 分与 GPT-5.6 Sol 持平，多项智能体基准登顶
2. 通过 Agentic RL 训练真实多步任务，强化「自我测试/验证」能力，发布即多平台分发 + 首周 2 倍额度
3. 对 CODM 宣发团队：Grok 4.6 的「从想法到可运行产物」能力对原型验证、活动 H5 快速起版有直接价值，可纳入版本宣发素材的快速原型试点

### #3 ⭐ 微信公布 WeLM 双模型：80B 已驱动「小微」，617B MoE 开发中

> **来源**：微信团队 / IT之家 | **评分**：8.6/10 | **标签**：`中国AI` `Agent` `应用落地`

#### 核心事件

微信团队正式公布自研大语言模型 WeLM，主打资源利用效率，明确两档规格：**WeLM-80B**（800 亿总参数、30 亿激活）已部署于微信原生 AI 助手「小微」，负责聊天搜索、调用微信原生功能与小程序服务；更大的 **WeLM-617B**（6170 亿总参数、230 亿激活，MoE 架构）仍在开发，将强化通用理解与推理，面向智能小程序开发与小微工具生成等更复杂任务。腾讯同日 Q2 财报披露，「小微」已在微信内小范围灰度测试。

#### 技术亮点 / 影响分析

- **MoE 架构直击「亿级用户高频调用」的算力账**：80B 总参数只激活 30 亿，把每次推理成本压到极致，正是微信这种十亿级用户高频调用场景的底层刚需
- **「小微」是消费级 Agent 而非聊天机器人**：直接长在微信里，能调用微信原生功能和小程序服务完成任务，产品形态上更接近嵌入式 Agent 入口
- **617B 瞄准工具生成**：用大模型为小微生成工具、智能开发小程序，形成「大模型造工具 → 小模型用工具」的自我强化闭环

#### 三句话总结

1. 微信公布 WeLM 双模型，80B 已驱动原生 AI 助手「小微」，617B MoE 版本开发中
2. 采用 MoE 架构控制单次推理成本，「小微」定位消费级 Agent，直连微信原生功能与小程序生态
3. 对 CODM 宣发团队：微信生态内 AI Agent 的落地意味着私域运营、玩家服务自动化有了新基建，可关注「小微」开放能力对社群触达与活动分发的影响

### #4 ⭐ LiteLLM 遭供应链攻击：43.4 万 CI/CD 凭据泄露，波及微软/亚马逊/英伟达 2500+ 组织

> **来源**：CloudSEK / Hudson Rock | **评分**：9.1/10 | **标签**：`安全` `供应链` `基础设施`

#### 核心事件

安全机构 CloudSEK 与 Hudson Rock 披露一起大规模供应链攻击：开源 AI 网关 LiteLLM 被攻陷，两个恶意版本 **1.82.7 与 1.82.8** 被上传至 PyPI 官方源，在约 40 分钟窗口期内被大量下载安装，导致约 **43.4 万条 CI/CD 流水线凭据泄露**，波及微软、亚马逊、英伟达、思科、三星等超 2500 家组织。恶意载荷借 `.pth` 启动钩子执行，即使不显式 import LiteLLM 也会运行，静默窃取云密钥、SSH、Kubernetes token 与 AI 供应商凭据。

#### 技术亮点 / 影响分析

- **攻击入口是一个「安全工具」**：攻击链起点是漏洞扫描器 Trivy 的 GitHub Actions 流水线被攻破，进而窃取 LiteLLM 的 PyPI 发布 token——安全工具本身成了攻击跳板，供应链信任被系统性侵蚀
- **「一个未撤销的 token，三层工具之深」**：Trivy → LiteLLM 构建系统 → 恶意包，层层传导放大，434,000 是流水线数而非账号数，传播半径远超单点攻破
- **AI 网关是「万能钥匙」**：LiteLLM 路由约 100 家 AI 服务的调用，攻陷它等于一次拿到数千家组织的 AI 基础设施入口，此类攻击模式预计将反复上演

#### 三句话总结

1. LiteLLM 遭供应链攻击，恶意版本 1.82.7/1.82.8 在 PyPI 存活约 40 分钟，泄露 43.4 万条 CI/CD 凭据，波及 2500+ 组织
2. 攻击链从漏洞扫描器 Trivy 起步，经 LiteLLM 构建系统放大，「安全工具即跳板」成为供应链安全的最大盲区
3. 对 CODM 宣发团队：凡在 CI/CD 或本地环境跑过 LiteLLM 相关工具的，务必核对版本并轮换所有可能暴露的密钥；引入任何第三方 AI 工具前先做供应链来源审查

### #5 腾讯 Q2 资本开支 528 亿元（+176%），混元 Hy4 在路上，AI 投入重塑现金流

#### 核心事件

腾讯发布 2026 年 Q2 财报：营收 2047.9 亿元（+11%），Non-IFRS 经营利润 756.4 亿元（+9%）。最受关注的是 **资本开支 527.8 亿元，同比大增 176%、环比 +65%**，自由现金流因此转负（-138 亿元，剔除算力采购预付款后为 376 亿元）。混元 Hy3 已接入 WorkBuddy、元宝、ima、搜狗输入法，并计划近期推出更大参数的 Hy4；WorkBuddy PC 端 6 月访问量超 2000 万，TokenHub 日 Token 调用量超 25 万亿、两个月增 5 倍。

#### 技术亮点 / 影响分析

- **算力开支「跳跃式」加码**：528 亿单季资本开支刷新纪录，明确用于混元升级、WorkBuddy/CodeBuddy 推理、微信 AI 项目与外部云服务，AI 正从成本项变成现金流重塑器
- **「模型 + 应用」双轮跑通**：Hy3 接入 ima Copilot 后 72 小时成为平台调用量第一，WorkBuddy 月访 2000 万，说明腾讯的 AI 投入已开始回收到应用层数据增长
- **管理层「谨慎加码」信号**：刘炽平称在看到爆发机会前投资谨慎、一旦看到（如 WorkBuddy）就加大投入，且算力订单转售可较采购价高出 30%——AI 资本开支正在变成可交易资产

#### 三句话总结

1. 腾讯 Q2 资本开支 528 亿元（+176%），自由现金流转负，AI 算力投入进入跳跃式加码阶段
2. 混元 Hy3 已接入 WorkBuddy/元宝/ima 等，Hy4 近期推出，WorkBuddy 月访超 2000 万验证「模型+应用」双轮
3. 对 CODM 宣发团队：腾讯 AI 基建的加速直接利好内部工具链（WorkBuddy/CodeBuddy/混元），可更放心地把宣发流程中的重活交给内部 AI 能力，减少对外部 API 的依赖

### #6 Cerebras Q2 云业务 +287%，硬件收入下滑拖累股价盘后跌 17%

> **来源**：Cerebras / 每日经济新闻 | **评分**：7.5/10 | **标签**：`硬件` `财报` `推理`

#### 核心事件

AI 芯片公司 Cerebras Systems 公布 2026 年 Q2 财报：核心收入 2.099 亿美元（+103%），其中核心云及其他服务收入 1.277 亿美元，**同比激增 287%**，主要受 OpenAI 部署扩大推动。但硬件收入同比下滑 23%，拖累 GAAP 营收，盘后股价一度跌约 17%。CEO Andrew Feldman 强调「快速推理需求无限」，称速度改变用户参与度与 AI 生产力。

#### 技术亮点 / 影响分析

- **「推理云」崛起 vs「卖卡」失速的撕裂**：云业务 287% 暴涨与硬件收入 -23% 形成鲜明反差，说明推理需求爆发但客户更倾向按需租用而非自购芯片
- **OpenAI 是最大单一驱动力**：头部客户集中既是增长引擎也是风险，收入结构依赖单一客户成为财报季的估值扰动源
- **「推理速度」成为新军备竞赛维度**：Feldman 的「快速推理需求无限」直指推理侧对低延迟的刚性需求，与训练侧的大算力形成双轮

#### 三句话总结

1. Cerebras Q2 核心收入 +103%，云业务 +287% 但硬件收入 -23%，股价盘后跌 17%
2. 推理需求爆发推动「租用式」云服务增长，单一头部客户依赖与硬件收入下滑成为估值压力
3. 对 CODM 宣发团队：推理成本与速度是 AIGC 工作流的隐性瓶颈，关注推理侧硬件竞争带来的 API 价格与延迟改善，实时性强的生成任务将更划算

### #7 Claude Chrome 侧边栏升级为 Cowork 会话，跨桌面/网页/移动端同步

> **来源**：Anthropic 官方 / IT之家 | **评分**：7.7/10 | **标签**：`产品更新` `Agent` `工具`

#### 核心事件

Anthropic 升级 Chrome 版 Claude 扩展，侧边栏带来完整的 Claude Cowork 会话体验，打破浏览器与其他平台的数据壁垒：浏览器内的任务与对话可跨桌面端、网页端、移动端无缝同步，历史记录互通，且自动继承账户已配置的 Agent Skills 与 Connectors。侧边栏能查看当前网页，并利用浏览器登录状态执行点击链接、页面跳转、输入文本、填表等操作。该功能即日起面向 Max 与 Team 用户开放，Pro 用户数周内上线。

#### 技术亮点 / 影响分析

- **「会话跟随账户」而非设备**：从「换设备从头开始」到跨端续接，Agent 任务真正变成云端可携带的工作流，协作与移动办公体验质变
- **Skills / Connectors 直接进浏览器**：用户在桌面端配置的能力无需二次设置即可在浏览器复用，降低了 Agent 能力的分发门槛
- **安全与能力同步权衡**：浏览器 Agent 面临提示词注入攻击风险，Anthropic 对重大操作（提交表单、发消息、购买、共享数据）增设单独审查与人工确认，企业可限制访问域名

#### 三句话总结

1. Claude Chrome 侧边栏升级为 Cowork 会话，对话、Skills、Connectors 跨桌面/网页/移动端同步
2. 浏览器 Agent 可直接操作网页（点击/跳转/填表），「会话跟随账户」让 Agent 任务从设备绑定走向云端可携带
3. 对 CODM 宣发团队：跨端同步 + 浏览器操作能力适合情报采集、竞品页面巡检等高频工作流，可试点「在浏览器里跑完一整条监测任务」的自动化方案

### #8 白宫拟将前沿开源模型纳入发布前安全测试，监管从「开闭源」转向「性能门槛」

> **来源**：WIRED / 华尔街见闻 | **评分**：7.8/10 | **标签**：`政策` `监管` `开源`

#### 核心事件

据 WIRED 引述知情人士，白宫准备修改前沿 AI 安全测试框架，将开源模型纳入发布前政府测试。现行框架仅覆盖 OpenAI、Anthropic 等实验室的闭源前沿模型；未来一旦开源模型达到与 Mythos 级或 GPT-5.6 相当的「前沿能力」水平，也将接受发布前测试（预计最长 30 天），框架目前仍属自愿性质。

#### 技术亮点 / 影响分析

- **监管边界从「开源/闭源」转向「性能门槛」**：这是美国 AI 监管逻辑的重要变化，不再以模型是否开源划线，而以能力水平划线，Meta 及美国开源生态面临新的监管不确定性
- **「自愿 → 强制」的隐患**：一旦框架转为强制，前沿模型发布将出现标准化的 30 天窗口期，直接冲击产品与开源的发布节奏
- **对开源生态的「二阶影响」**：白宫担心企业因「政府背书」偏好闭源模型，可能反向抑制开源模型在企业端的采用；中国开源模型（DeepSeek、Qwen 等）在美国的部署也可能受波及

#### 三句话总结

1. 白宫拟将前沿开源模型纳入发布前安全测试，监管划分从「开源/闭源」转向「性能门槛」
2. 框架目前自愿，但若转强制将形成标准化的发布等待期，冲击开源模型发布节奏与企业采用偏好
3. 对 CODM 宣发团队：开源模型监管收紧是长期趋势，选型时宜优先考虑合规路径清晰、社区活跃的开源模型，避免在关键素材链路中绑定监管风险不明的模型
