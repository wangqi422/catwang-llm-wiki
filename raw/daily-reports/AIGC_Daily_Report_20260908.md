### #1 ⭐ GPT-6 Astra 自主通关《传送门》：3336 次工具调用、$571、24 小时

> **来源**：IT之家 / The Decoder / TechEBlog | **评分**：8.6/10 | **标签**：`模型` `Agent` `游戏`

#### 核心事件

AI 爱好者 **CozyBlaze** 把 OpenAI 新旗舰 **GPT-6 Astra** 通过 **MCP（Model Context Protocol）** 接入改造版 SourcePauseTool，以「暂停—截图分析—规划—执行」的循环，**首次让大模型无人工干预自主通关了 Valve 的 3D 解谜游戏《传送门》**——跑完所有测试舱、逃脱关卡，直到和 GLaDOS 的最后对话、字幕滚完，全程没有人碰键盘。整个过程共 **3336 次工具调用**，耗时约 **23 小时 43 分钟**（实际有效游玩约 2 小时，其余时间是模型「暂停思考」），按 OpenAI 官方报价折算 API 成本 **$571.18**（约 3838 元，实际由 $200/月的 Codex Pro 订阅覆盖）。对比之下：此前 Opus 5 只打到第 10 舱就卡死，Fable 5 没走出第 8 舱。

#### 技术亮点 / 影响分析

- **从「看懂屏幕」到「操作电脑」的闭环跃迁**：GPT-6 Astra（9 月 3 日发布）在 OSWorld 2.0 完成率 72.6%、ScreenSpot-Pro 屏幕元素定位准确率 92.7%，这次把能力延伸到三维物理空间——**长链条自主决策 3336 步无目标漂移**，被视为 AI 从「理解世界」迈向「操作世界」的标志性实验
- **「暂停—分析—执行」范式 + TAS 级精准**：模型思考时游戏冻结，输入指令后 SourcePauseTool 播放输入，配合原生 TAS 回放，动作精准到像「工具辅助速通」；这也解释了为什么剪辑视频只有 2 小时、全程却近 24 小时
- **诚实地说，这不是通用游戏智能**：《传送门》是被攻略/视频/维基「喂饱」的已知谜题，通关不等于能从零破解陌生游戏；CozyBlaze 自己也承认「不应视为标准化基准」，并已开源控制器代码、补丁与脱敏日志，下一步瞄准《传送门 2》与无攻略的原创关卡

#### 三句话总结

1. GPT-6 Astra 经 MCP 接入改造版 SourcePauseTool，以「暂停—分析—执行」循环自主通关《传送门》，3336 次工具调用、近 24 小时、成本 $571，前代模型卡在第 8/10 舱
2. 意义在于把「看懂屏幕」升级为「操作电脑/操作三维空间」的闭环能力，Agent 的长链条自主决策首次无目标漂移地跑通一个完整游戏
3. 对 CODM 宣发团队：**这条消息是「游戏 + AI Agent」最直接的对撞信号**——同样的「截图→理解→规划→执行」范式，未来可迁移到「AI 自动跑图做素材/自动验收关卡表现/自动生成游戏演示」；但 $571 打一个老游戏也提醒我们：**Agent 的「长链条自主」目前又贵又慢，宣发侧的自动化优先做「短流程、可断点、可人工复核」的任务，别一上来就押长程全自动**

### #3 ⭐ 《西雅图时报》+《新闻日报》起诉 OpenAI/微软，要求销毁模型

> **来源**：The Verge / 环球网 / MediaNama | **评分**：7.7/10 | **标签**：`版权` `诉讼` `行业`

#### 核心事件

9 月 4 日（当地时间），美国两大新闻机构**《西雅图时报》（Seattle Times）与《新闻日报》（Newsday）**正式向纽约南区联邦法院提交诉状，将 **OpenAI 及其合作伙伴微软一并告上法庭**，指控两家企业未经授权抓取新闻报道（含付费墙内容）用于训练 ChatGPT、Copilot 与 Bing AI，构成版权侵权。诉状指控 AI 在回答查询时会大段直接复述新闻原文（举例：模型仅凭标题 + URL 就复现了《西雅图时报》一篇关于波音 737 MAX 危机的文章中的**连续 88 个词**）。本次诉讼诉求相当强硬：除经济赔偿外，还请求法院下达法令**强制销毁所有收录两家媒体报道的训练数据集、以及吸收了相关新闻内容的 AI 模型**。

#### 技术亮点 / 影响分析

- **版权诉讼的「诉求升级」**：从「要赔偿」升级到「要求销毁模型 + 数据集」，若获支持将直接冲击大模型的训练与权重——这是继《纽约时报》（2023）、韦氏词典、大英百科全书、近 400 家地方报纸集体维权之后的又一起标志性诉讼
- **法理对撞正在白热化**：9 月 2 日美国司法部刚提交简报支持 OpenAI 的「合理使用（fair use）」抗辩，主张「用公开数据训练 LLM 不构成侵权」；本案与司法部立场形成正面对撞，最终判例将深刻影响 AI 训练的版权边界
- **「训练-输出」的证据链被锁定**：诉状不仅指控「抓取训练」，还指控「输出复现」——88 词逐字复述、以及 AI 直接给答案导致读者不再跳转原站、损害流量/订阅收入，把「训练侵权」和「生成物侵权」两条线都抓在手里

#### 三句话总结

1. 《西雅图时报》与《新闻日报》起诉 OpenAI 和微软，指控抓取付费新闻训练 ChatGPT/Copilot 并逐字复述（88 词案例），诉求包括销毁训练数据与 AI 模型
2. 这是「要赔偿」升级为「要销毁模型」的标志性诉讼，与 9 月 2 日司法部支持 OpenAI 合理使用的简报正面对撞，最终判例将定调 AI 训练版权边界
3. 对 CODM 宣发团队：**「AI 训练版权」的法律边界正在收口，且第一次把「生成物逐字复述」也列进侵权**——宣发侧用 AI 生成文案/素材时，务必保留「参考素材的授权链路」并做「去重/改写」审查，避免大段复述来源文本；商业发布的 KV/海报/视频优先用有明确授权的素材库，别在「版权归属模糊」的二手素材上踩雷

### #4 微软论文：LLM Agent 16 步长程任务崩到 0–33%，成功服从几何衰减

> **来源**：微软 / arXiv（2609.01660）/ AGI Hunt | **评分**：7.6/10 | **标签**：`Agent` `可靠性` `长程`

#### 核心事件

微软发布论文（arXiv:2609.01660），对 **9 个模型（含 1.2B–671B 开源模型与 3 个闭源模型）、4 类任务族、5 档步数、3 种上下文设定下的 10664 条轨迹**做了长程 Agent 可靠性测量，结论刺耳：**LLM Agent 的任务成功率随步数服从「几何衰减」定律**——每步都有一个独立误差概率，误差会乘法式累积。在智能体工具调用任务（ToolQA）上，短任务近乎满分的模型，**到第 16 步成功率崩到 0–33%**。更反直觉的是：**衰减由「步数」而非「上下文长度」驱动**——人为缩短上下文反而让衰减更陡（logit 斜率 -0.69 vs -0.44，p=3e-6），直接否定了「迷失在中间（lost-in-the-middle）」的解释。

#### 技术亮点 / 影响分析

- **「几何衰减」给 Agent 画了天花板**：单一「每步可靠性参数」就足以刻画整条成功率曲线，它随模型规模上升但在远低于 1 处饱和——意味着**光靠把模型做大，无法消除长程崩溃**，长链条任务的失败是数学必然而非工程瑕疵
- **「步数 > 上下文」的颠覆性发现**：过去普遍以为「上下文变长→信息丢失」是主因，论文证明「截短上下文」反而更糟——**真正的瓶颈是每一步动作的累积误差**，靠修上下文救不回来
- **落地建议直白**：① 在真实工作流长度上测试 Agent（别信短基准的 95%）；② 测量每步可靠性；③ 在「坏步骤污染下游」之前插入检查点/人工复核

#### 三句话总结

1. 微软论文用 10664 条轨迹证明：LLM Agent 成功率随步数「几何衰减」，ToolQA 任务从近满分崩到 16 步的 0–33%
2. 关键发现是「步数驱动衰减、而非上下文长度」，每步误差乘法累积，光靠放大模型无法消除，长程崩溃是结构性难题
3. 对 CODM 宣发团队：**这是对「全自动 Agent 流水线」的一记清醒剂**——宣发侧的自动化（批量生图/竞品采集/文档撰写）务必「短流程 + 每步检查点 + 人工复核」，别把 10 步以上的长链条交给 Agent 裸跑；「步数驱动衰减」也提示：**把长任务拆成多个可独立验证的短任务，比一个超长 Prompt 更可靠**

### #5 面壁智能开源 MiniCPM5-2B：4B 以下开源榜首，Apache 2.0 + vLLM Day-0

> **来源**：面壁智能 OpenBMB / MarkTechPost / Artificial Analysis | **评分**：7.5/10 | **标签**：`开源` `端侧` `国产`

#### 核心事件

9 月 7 日，**面壁智能（OpenBMB）开源端侧小模型 MiniCPM5-2B**。这是 MiniCPM5 系列继 1B 后的第二款，**总参数约 2.6B（非嵌入参数约 1.98B）的稠密模型**，采用标准 LlamaForCausalLM 架构、42 层 Transformer、原生上下文 128K。在 **Artificial Analysis Intelligence Index v4.2 上拿到 15 分，登顶 4B 参数以下开源模型榜首**；官方自测 34 项基准平均 53.9，高于同级的 Qwen3.5-4B（51.1）、granite-4.2-3B（42.7）等。权重以 **Apache 2.0** 开源，vLLM v0.21.0、SGLang、Ollama、LM Studio 等提供 **Day-0 支持**。

#### 技术亮点 / 影响分析

- **「工具调用」是最大护城河**：τ²-Bench Telecom 97.1、BFCL v4 66.6，工具调用能力在同级断崖式领先（对比基线 6.8），LiveCodeBench v6 69.1、SWE-bench Verified 46.4——**这是一款「面向 Agent/工具调用」的端侧模型，而非通用知识模型**
- **「SFT→RL→在线策略蒸馏（OPD）」的可验证配方**：后训练用 400B tokens 深度思考 SFT 打底，再训 16 个 RL 专家模型（含 5 个 agentic 专家），最后 OPD 蒸馏回单一模型；**数据也全开源**（UltraData 系列 + 中间 checkpoint），每一步增益都可复现
- **「小模型能打」的工程信号**：2B 参数跑到逼近 4B 甚至部分超 4B 的水平，配合 Apache 2.0 + 多家推理框架 Day-0，把「本地跑能用的 Agent 模型」的落地门槛大幅拉低

#### 三句话总结

1. 面壁智能开源 MiniCPM5-2B（2.6B 稠密、128K 上下文），登顶 4B 以下开源模型榜首，Apache 2.0 + vLLM/SGLang/Ollama Day-0 支持
2. 最大亮点是「工具调用/Agent」能力同级断崖领先（τ²-Bench 97.1），且训练数据与中间 checkpoint 全开源、配方可复现，是「端侧 Agent 模型」的标杆
3. 对 CODM 宣发团队：**「小模型 + 端侧 + 工具调用」的组合正在成熟**——未来宣发侧完全可以在本地/私有化跑一个「懂竞品、会调工具」的轻量 Agent（做素材分类、文案抽取、竞品监控），不依赖云端大 API、不担心数据外泄；「数据 + checkpoint 全开源」也提供了一个可对标复现的国产技术路线

### #6 AMD + vLLM：MI355X 智能体负载 19 天性能暴涨 11 倍

> **来源**：AMD / SemiAnalysis / 网易 | **评分**：7.4/10 | **标签**：`算力` `推理` `AMD`

#### 核心事件

9 月 7 日，AMD 官方甩出一组数据：在 **MI355X 加速卡**上，**vLLM 框架跑 MiniMax M3 模型的智能体（Agentic）工作负载，性能提升 11 倍**，而从开始优化到公布结果**全程不到 19 天**。这次提升**完全靠软件优化、没换硬件**——核心动作是优化长上下文注意力算子（智能体负载里最吃计算资源的部分），再叠加其他算子优化。AMD 特意点了一句「这就是 ROCm 软件栈的威力：硬件买一次，后续通过软件优化持续获得性能更新，不用再花钱」。

#### 技术亮点 / 影响分析

- **软件栈正在成为硬件竞争力的核心变量**：19 天 11 倍，节奏快得不像传统硬件厂商——AMD 在 vLLM + ROCm 的配合上已经形成「发现问题就上、优化完就发」的快速迭代打法，与英伟达「护城河在软件栈」的逻辑正面对冲
- **直指「智能体负载」这一具体场景**：不是通用跑分，而是 Agentic Workloads——长上下文、多轮 KV-cache 复用正是智能体推理的成本重灾区，优化这一环对「按 token 计费」的 Agent 应用最划算
- **「纯软件收益」的落地意义**：手里已有 MI355X 的团队等于白捡 11 倍性能；对还在选卡的团队，「买卡 + 等软件优化」的性价比叙事开始成立，CUDA 护城河被进一步削弱

#### 三句话总结

1. AMD 公布 MI355X 上 vLLM 跑 MiniMax M3 智能体负载 19 天性能提升 11 倍，纯软件优化、不换硬件，核心是长上下文注意力算子优化
2. 信号是「软件栈正成为硬件竞争力核心」——ROCm 的快速迭代正削弱 CUDA 护城河，且直指智能体（长上下文、KV-cache）这一推理成本重灾区
3. 对 CODM 宣发团队：**推理侧的「软件红利」意味着跑 Agent 的算力成本还在持续下探**——宣发侧不必绑定单一芯片生态，选型时把「软件栈迭代速度」纳入考量；更实在的是：**同样的预算，未来能跑更多、更长、更便宜的智能体任务**，自动化流水线的成本天花板在松动

## §3 趋势 & 工具

### #7 NVIDIA Sol-H3：MiniMax-H3 视频生成速度首次超过播放速度

> **来源**：NVIDIA / MiniMax / AGI Hunt / RuntimeWire | **评分**：7.5/10 | **标签**：`视频生成` `推理` `MiniMax`

#### 核心事件

英伟达 Sol 团队联合 MiniMax 发布 **Sol-H3**——面向 MiniMax-H3 视频模型的端到端推理加速栈，在单台 8× B300 Blackwell 系统上，**生成 5 秒（1344×768、24fps、带立体声）视频仅需 1.653 秒，首次跑出「比播放还快」的成绩**（约为观看速度的 3 倍）。对比标准 50 步 H3：5 秒片段从 18.25s 降到 1.653s（**11.04 倍**）、10 秒从 50.66s 降到 3.732s（13.57 倍）、15 秒从 99.5s 降到 6.612s（15.05 倍）。代码以 **Apache 2.0** 开源，并通过 Reactor API 提供沙箱试用。

#### 技术亮点 / 影响分析

- **「四步 FastH3 适配器」是提速核心**：把生成路径从 49 次 transformer 前向压缩到 4 次，配合动态稀疏注意力（设置时间 1.206→0.285ms、降 76.4%）、融合算子、VAE 并行解码（7.55s→0.602s），单卡还释放约 24GB 显存
- **「快过播放」是真正的拐点**：一旦生成稳定快过实时播放，**连续、交互式的视频生成在结构上成为可能**——「边看边生成、提示词实时改写画面」从理论走向工程，而非过去「提交→等待→看结果→再调」的批处理模式
- **诚实标注的边界**：1.653s 是 8×B300 的「热推理 + 四步有损加速 + 不含模型加载/MP4 编码」的中位数；单卡 B300 仍需 13.745s（低于播放速度），默认 speed 档有损、另有 dense 档保真——不是任何机器都能「快过播放」

#### 三句话总结

1. 英伟达 Sol-H3 让 MiniMax-H3 视频生成在 8×B300 上做到 5 秒视频 1.653 秒生成（11 倍加速），首次「快过播放」，Apache 2.0 开源
2. 核心是「四步 FastH3 适配器 + 稀疏注意力 + 并行 VAE 解码」，「快过播放」是视频生成从「批处理」走向「交互式/连续生成」的结构性拐点
3. 对 CODM 宣发团队：**这是宣发视频制作最直接的效率利好**——「边生成边调」的交互式出片、批量生成候选分镜、A/B 试不同运镜的成本都会大幅下降；但要注意「8×B300 是门槛、默认 speed 档有损」，落地时按「质量要求」选 dense 档、按「速度要求」选 speed 档，别被「快过播放」的标题带偏了单卡预期

### #8 OpenAI ChatGPT Work 推出个人写作风格学习功能

> **来源**：OpenAI / Greg Brockman | **评分**：7.3/10 | **标签**：`工具` `写作` `ChatGPT`

#### 技术亮点 / 影响分析

- **「风格对齐」成为企业 AI 写作的新战场**：从「通用生成」走向「学你的语气/句式/排版」，让 AI 产出的工作文档更像「本人写的」，是企业级写作助手提升「可用性」与「采纳率」的关键一步
- **「个人风格库」的隐性价值**：风格一旦被模型固化，团队内部可形成「统一对外话术风格」，对品牌一致性、跨人协作的效率提升有直接价值
- **竞争信号明确**：ChatGPT Work 与 Claude Cowork 在企业写作工具上贴身肉搏，后续大概率会延伸到「风格 + 记忆 + 上下文」的深度整合

#### 三句话总结

1. OpenAI 在 ChatGPT Work 上线个人写作风格学习功能，让模型学习并复现用户自己的写作风格，Greg Brockman 官宣
2. 标志「风格对齐」成为企业 AI 写作的新竞争点——从通用生成走向「学你的语气/句式」，提升工作文档的可用性与采纳率
3. 对 CODM 宣发团队：**「风格学习」正是宣发侧的刚需**——团队可借此固化「瘦普诙谐口吻 / 品牌统一话术 / 固定版式」，让 AI 产出的宣发文案、周报、简报都保持一致的品牌语气；建议先梳理一套「品牌写作风格样例集」喂给模型，把「风格」从玄学变成可复用资产
