### #1 ⭐ 百度开源 ERNIE 5.5 Flash Base：280B MoE / 每 token 激活 14B，33.5T tokens 预训练，推理支持 1M 上下文

> **来源**：[百度文心 ERNIE 官方博客](https://yiyan.baidu.com/) · [快科技 / 网易](https://www.163.com/dy/article/LB1I9L1D0511CPVM.html) · [腾讯研究院 AI 速递 20261106](https://www.sohu.com/a/1097767586_455313) · [AITOP100 每日 AI 资讯](https://www.aitop100.cn/ai-daily-2026-11-05) | **评分**：9.3/10 | **标签**：开源基座 / 国产模型 / 长上下文 / 稀疏 MoE

#### 核心事件
11 月 5–6 日，百度正式开源最新基座模型 **文心 ERNIE 5.5 Flash Base** 的预训练终点权重，FP8 与 BF16 两个版本已上线 Hugging Face。模型采用稀疏 MoE 架构，**总参数 2800 亿、每 token 仅激活 140 亿**，用 **33.5 万亿 tokens** 从零预训练；预训练上下文 128K，微调与推理阶段最长支持 **100 万 token**。官方自报 MMLU 93.3、MMLU-Pro 78.4、HumanEval+ 82.3、MBPP+ 81.5，宣称同尺寸 SOTA，超过 DeepSeek-V4-Flash-Base、Hy3-preview-Base、MiMo-V2.5-Base 等。

#### 技术亮点 / 影响分析
- **效率是设计目标，不是堆参数**：43 层中 37 层采用「每 128 个 token 只缓存一条」的压缩注意力，共 512 个路由专家、每 token 选 10 个；训练侧用 Muon 优化器 + FP8 混合精度 + 自研 FlashMask-4 注意力算子，把长文本的显存与计算一起压下来。
- **开源的是「基座」不是「助手」**：纯预训练权重，未经过中训练与后训练，下载后不能当成熟聊天机器人用，定位是给开发者与企业做指令微调、领域适配与强化学习；采用自定义许可证，商用前需单独核对条款。
- **与昨日形成对照**：11-05 期 #7 讲的是 65B / 276B 的「小而快」编码模型，今天这条是超大稀疏基座——同一天里国产开源把「容量」和「每 token 只算 14B」同时做进一个可自部署的底座。
- **需要保留的判断**：全部跑分为厂商自评，评测环境与验证脚本不统一，跨实验室横比只作参考；后训练版本官方称将随后推出。

#### 三句话总结
1. 百度开源 280B 总参 / 14B 激活的 MoE 基座，33.5T tokens 预训练、推理支持 1M 上下文，FP8 与 BF16 权重已上 Hugging Face。
2. 把「超大容量」与「每 token 只算 14B」同时做进一个可私有化部署的国产底座，长上下文按省缓存设计。
3. **对 CODM 宣发团队**：可作为品牌素材生成、文案与长规范理解的私有化微调底座，整套视觉规范与历史资产能一次塞进上下文，不必把品牌资料交给公有云 API。

### #2 ⭐ Thinking Machines 发布 Inkling 2 Small：594B MoE，AA 指数 31，下周 Apache 2.0 开放全量权重

> **来源**：[Thinking Machines Lab 官方公告](https://thinkingmachines.ai/news/inkling-2-small/) · [官方模型卡](https://thinkingmachines.ai/model-card/inkling-2-small/) · [Artificial Analysis](https://artificialanalysis.ai/) · [Arena / Mira Murati X](https://x.com/miramurati) | **评分**：9.2/10 | **标签**：模型发布 / 开放权重 / Agent 编码 / 视觉自检

#### 核心事件
11 月 5 日，Mira Murati 的 Thinking Machines Lab 发布第二代模型 **Inkling 2 Small**：**594B 总参 / 17B 激活**的稀疏 MoE（48 层、每 token 路由 8 of 384 专家），原生支持图像输入与 variable effort，上下文窗口最长 **1M tokens**。Artificial Analysis Intelligence Index v5 得分 **31**（官方模型卡列 30.6），远超第一代；Code Arena WebDev 榜单约 **1654 分**，被列为美国开放权重模型第一。当前先通过 **Tinker** 平台以闭源权重提供微调、采样与 Playground 试用，官方明确承诺**下周完成外部安全测试与红队后以 Apache 2.0 开放全量权重**，届时 checkpoint 可下载。

#### 技术亮点 / 影响分析
- **训练方法比参数更值得看**：更高效的预训练 + 一次大规模统一 RL，在数十万条长程编码任务上跨多种 agent harness 与上下文压缩策略训练；奖励不再只有单元测试，很多任务配了「agentic RL grader」评估模型**怎么解题**而不只是代码是否跑通。早期 checkpoint 曾以 Fledge-Alpha 之名在 OpenCode 上做真实世界验证。
- **视觉自检闭环**：能读视觉反馈迭代搭建与精修网站、游戏、3D 设计——官方演示包括用 Three.js 无素材生成整座可运行的城市模拟器、用 Python 写出能启动 Linux 内核的 PC 模拟器、在 Blender 里改水面与烟囱。
- **autoresearch 已跑通**：官方演示模型自主在 Tinker 上训练 Qwen3.5-4B 做时序预测，自己写评估器、试数据集与 SFT/RL 配方，**4.5 小时 / 426 美元**把预测分翻了一倍以上。
- **与昨日是连续剧，不是重复**：11-05 期 #7 报道的 Cognition SWE-2 Flash 正是「基于 Thinking Machines 的 Inkling-Small」；今天底座正式官宣，并给出开放权重时间表。
- **需要保留的判断**：官方明确「仍落后闭源模型」（对齐评测低于 GPT-6.1 Sol），AA 指数 31 低于 Gemini 3.8 Flash 的 36.5；「美国开放权重第一」是在**尚未开权重**阶段的榜单表述，且下周能否如期放出取决于外部安全测试结果。

#### 三句话总结
1. Thinking Machines 发布 594B / 17B 激活的 Inkling 2 Small，AA 指数 31、支持图像输入与 1M 上下文，承诺下周 Apache 2.0 开放全量权重。
2. 把长程 Agent、视觉自检与「过程评分」RL 做进一个可微调底座，并首次给出从闭源试用走向开放权重的明确路径。
3. **对 CODM 宣发团队**：内部 Agent 工具链可先在 Tinker 上试「视觉自检」（自动检查生成海报、H5 页面的成品是否符合版式），等权重开放后再评估私有化部署与成本。

### #3 ⭐ 月之暗面发布 Kimi Hosted Agents：把 Agent 的 Harness 做成 7×24 云托管服务

> **来源**：[Kimi 官方文档](https://platform.moonshot.cn/) · [上海证券报 / 中国证券网](https://www.cnstock.com/commonDetail/824356) · [澎湃新闻](https://m.thepaper.cn/newsDetail_forward_34412840) · [每日经济新闻](https://new.qq.com/rain/a/20261106A03A3V00) | **评分**：9.0/10 | **标签**：托管智能体 / Harness / 企业服务 / 商业化

#### 核心事件
11 月 5 日，月之暗面正式发布 **Kimi Hosted Agents（托管智能体）**，把支撑 Agent 运行的 **Harness 框架作为云端服务**提供给企业与开发者。企业无需自建代码执行环境，也不必自己处理上下文管理、工具调用、权限控制、任务中断恢复，即可获得 **7×24 小时托管环境**，支持长程任务执行与多智能体协作。服务提供独立沙箱、网络权限控制、随时中止会话与审计导出，配套 **140+ Skills 与 30+ 插件**，可接入自有工具与数据源；配合 Kimi Inference Hook 可在每次推理前按企业规则拦截敏感数据。首批提供 8 个金融 Agent 模板，目前仅向企业认证用户开放。计费由**模型 token + 沙箱运行时长 + 插件调用次数**三部分构成。

#### 技术亮点 / 影响分析
- **卖的东西变了**：从「卖模型推理 API」上移到「卖智能体运行环境」，竞争维度从评测分数转向生态厚度与信任半径。官方称企业自建一套可靠 Harness 常需数月并持续投入维护。
- **与前三天的连续剧**：11-03 期 #1 报 Kimi 游戏开发与创意工作解决方案（Agent 直操 Godot / Blender / Unity / UE，20 小时无人干预）；11-05 期已标注 K3.1 Pro 完整权重按 10-24 承诺放出并获昇腾 0Day 适配（本期不重复展开）；今天补上「运行环境托管」这一层——模型、方案、环境三段拼齐。
- **成本结构要拆开算**：token、沙箱时长、插件调用次数分别计价，长程任务的账单形态与单纯 API 调用不同，排产前需按三段分别估。
- **竞争短板写得很清楚**：AWS、阿里云等云厂商已有同类托管服务且握有更深的企业客户关系与基础设施纵深；Kimi 的优势在模型与 Agent 框架原生协同，短板在云基础设施。

#### 三句话总结
1. 月之暗面把 Agent 的 Harness 做成 7×24 云托管服务，提供 140+ Skills、30+ 插件、独立沙箱、网络权限控制与审计导出。
2. 行业竞争从「模型能不能跑」转向「运行环境能不能被托付」，模型厂商开始卖基础设施而非只卖 token。
3. **对 CODM 宣发团队**：批量出图、改稿、发布检查这类自动化流水线可以外包运行环境，不必自建沙箱与上下文管理；但要先定清楚三段计费口径与 Inference Hook 的敏感数据拦截规则。

### #4 ⭐ Google 发布 Gemini Omni 1.2 Flash：15 秒原生视频、降价 30% 至 $0.07/秒、多轮对话式改片

> **来源**：[Google 官方博客](https://blog.google/innovation-and-ai/technology/developers-tools/introducing-gemini-omni-1-2-flash/) · [Google Cloud 官方博客](https://cloud.google.com/blog/products/ai-machine-learning/gemini-omni-1-2-flash-generally-available) · [The Verge](https://www.theverge.com/ai-artificial-intelligence) · [Arena 文生视频榜](https://lmarena.ai/) | **评分**：8.9/10 | **标签**：视频生成 / 对话式编辑 / 品牌一致性 / 宣发工具

#### 核心事件
11 月 5 日，Google 发布并全量开放 **Gemini Omni 1.2 Flash**，覆盖 Gemini API、Google Cloud、Google Vids、Gemini for business、Flow、AI Studio，同步上线 OpenRouter 与 fal。原生视频生成与编辑上限从 1.1 的 **10 秒提升到 15 秒**，可在一秒步进里指定 3–15 秒；720p 价格较 1.1 **下调 30% 至 $0.07/秒**。新增**多轮对话式编辑**：换产品、换背景、调光照、改天气、切画幅都不用重生成整段。参考图遵循显著增强，可组合角色 / 产品 / 风格图、最长 3 秒运动片段与音频线索，让人脸、服装、包装字体与**品牌色跨机位保持一致**。推荐工作流是 360p/720p 出草稿 → 对话改细节 → 放大到 1080p/4K；输出带不可见 SynthID 水印，企业可配 Provisioned Throughput。Arena 文生视频榜登顶。

#### 技术亮点 / 影响分析
- **账单从「重生成」换成「重编辑」**：改一处细节不再整段重跑，为不同受众、不同版位出多版广告的成本结构被直接改写。
- **品牌一致性正好补昨天的短板**：11-05 期 Images 2.6 的 GIF 实测里「背景与手部逐帧漂移、品牌资产需单独过合规」是主要痛点；1.2 Flash 官方点名包装字体与品牌色跨帧锁定，等于把一致性做进模型侧。
- **与 1.1 不是同一事件**：往期报道过 Omni 1.1 Flash 的 40 秒场景扩展与 4K 放大；1.2 是原生时长、降价、对话式编辑与参考遵循的**版本升级**，且首次在企业栈全量可用。
- **边界要说清**：官方承认快速体育动作、频繁改脚本、复杂物理仍在改进；音频参考需白名单；15 秒仍不是长片；发布时点尚无第三方质量复测，公开记录主要是官方博客与转述报道。

#### 三句话总结
1. Google 全量开放 Gemini Omni 1.2 Flash：15 秒原生视频、720p 降价 30% 至 $0.07/秒、多轮对话式改片、参考图锁定品牌细节。
2. 视频生成的竞争从「能不能出片」转到「能不能像剪片一样改片」，并重估单条素材的成本口径。
3. **对 CODM 宣发团队**：同一条角色 / 武器素材可对话式换背景、光照、画幅，批量产出多版位社媒短版，品牌色与字体跨帧更稳；适合分镜试片与快速迭代，但复杂动作镜头仍需人工终审。

### #5 ⭐ 可灵 Kling 4.0 Flash 全面开放并接入 Adobe：PS / PR / AE 官方插件 + MCP / CLI / API

> **来源**：[可灵 AI 官方公众号](https://klingai.com/) · [AIBase](https://news.aibase.com/tw/news/32109) · [AITOP100 每日 AI 资讯](https://www.aitop100.cn/ai-daily-2026-11-05) · [凤凰网科技](https://tech.ifeng.com/) | **评分**：8.7/10 | **标签**：视频工具 / 剪辑工作流 / MCP / 宣发

#### 核心事件
11 月 4 日晚，可灵 AI 官宣 **Kling 4.0 Flash 面向全球所有用户全面开放**，支持官网与 API 调用，并新增 **MCP、CLI 与第三方 AI 插件**接入；最关键的是打通 Adobe 专业影视软件——创作者可在 **Photoshop、Premiere Pro、After Effects** 内通过可灵官方插件直接调用 Flash 生成素材。Flash 是 Kling 4.0 家族的速度 / 性价比版本，生成 3–20 秒 720p 片段，支持文生视频、图生视频与 Omni Reference。完整版 Kling 4.0 已于 10 月 15 日全量开放（单次最长 30 秒、最多 10 个关键帧），Flash 于 9 月 28 日先小范围开放；本次是「扩到所有人 + 扩到 API 与插件」，**不是新模型首发**。

#### 技术亮点 / 影响分析
- **入口变化大于能力变化**：从「浏览器生成 → 导出 → 导入时间线」变成在剪辑台内直接生成草稿与试镜头，省掉来回导出；官方定位是打通从创意构思、素材生成到精细剪辑的完整链路。
- **可被 Agent 调用**：API + MCP + CLI 意味着生成能嵌进既有自动化流水线、由智能体按指令触发，不必人工开网页点按钮——与 #3 的托管 Harness 正好构成上下游。
- **分工清楚**：Flash 管快速迭代与高频创作，多关键帧、长镜头控制与高规格成片仍归完整版；本次也未改变 Kling 4.0 本身的能力上限。

#### 三句话总结
1. 可灵 Kling 4.0 Flash 全面开放，并接入 Photoshop / Premiere Pro / After Effects 官方插件、MCP、CLI 与 API。
2. 生成工具第一次把入口搬进专业剪辑软件的时间线里，同时变成可被智能体调用的流水线能力。

### #6 Runway 公开 57B 实时视频推理系统：8 → 4 张 H100 跑通 24fps 对话式数字角色

> **来源**：[Runway News](https://runwayml.com/news) · [凤凰网科技 / 网易](https://www.163.com/dy/article/LB1SJ5FR0556I485.html) · [AI HOT 聚合池](https://aihot.news/) | **评分**：8.5/10 | **标签**：实时生成 / 推理优化 / 数字人 / 算力

#### 核心事件
11 月 5–6 日，Runway 发布技术论文，首次详细披露实时视频对话产品 **Runway Characters** 背后的推理系统：一款约 **57B 参数**的自回归视频扩散 Transformer，能把一张静态图变成可实时交流的 AI 虚拟角色（真实人像、卡通或虚构角色均可），输出 704×1088 / **24fps**，根据对话内容实时生成面部表情、嘴唇动作与头部运动。单会话需约 **2.24 PFLOP/s** 有效算力，超过单张 H100 的密集 FP8 理论峰值。团队通过缓存管理、计算流程与 GPU 间通信优化，在 4 张 H100 上把单步耗时从 **240.9ms 降到 159.3ms**（提速 1.51×，持续 24.5fps），再引入计算与通信融合降到 **147.4ms**（整体 1.63×），**把单会话所需 H100 从 8 张砍到 4 张**。

#### 技术亮点 / 影响分析
- **实时视频不能靠批处理摊薄**：与语言模型不同，每位用户需要独立的实时生成服务，增加第二个会话几乎让计算耗时翻倍，因此优化必须落在单会话内部，而不是靠并发摊成本。
- **166.7ms 是硬门槛**：24fps 要求每 166.7ms 产出一组四帧，且整个对话过程持续维持；147.4ms 是压进这条线里的工程结果，缓存管理是其中关键改进。
- **门槛砍半决定能不能排期**：8 → 4 张 H100 直接决定数字人 / 虚拟主播能否从演示走进可预算的直播与互动投放。
- **边界**：论文为厂商自述，未披露商用定价与多会话并发的真实成本；704×1088 仍非广播级分辨率；实时对话中的长时间一致性未给出量化结果。

#### 三句话总结
1. Runway 用 57B 视频扩散模型配合推理优化，把实时对话数字人从 8 张 H100 压到 4 张、单步 147.4ms、跑通 24fps。
2. 实时视频生成的瓶颈是单会话算力与通信，而不是模型规模或并发批处理。
3. **对 CODM 宣发团队**：品牌虚拟角色 / 主播的实时互动门槛被砍半，直播预告、玩家问答、角色陪伴类素材的算力预算可以重新算一遍，再决定要不要做常驻互动位。

### #8 能生成 ≠ 能交付：Anthropic 与美联社签首份新闻内容授权；Google PLE 实测 91% 单项正确率只换来 41.3% 可行设计

> **来源**：[The Decoder](https://the-decoder.com/) · [IT之家](https://www.ithome.com/) · [雷峰网](https://www.leiphone.com/) · [CSDN DevPress 每日 AI 研究简报](https://devpress.csdn.net/aibjcy/6aec95ade5f4ca4eff8eb484.html) | **评分**：8.3/10 | **标签**：内容授权 / 评测基准 / 落地边界 / 合规

#### 核心事件
11 月 5 日两条信号同时落地。其一，**Anthropic 与美联社（AP）达成首份新闻内容授权协议**，这是该公司在与音乐出版商、书籍作者的版权诉讼之外，第一次与新闻机构建立正式内容授权关系。其二，**Google 与 Mercor 联合发布 PLE 测试**，量化工程 Agent 的「正确率泡沫」：共同创作任务中平均满足 **91% 的单项约束**，但满足全部硬性安全与可行性要求的设计项仅 **41.3%**；Claude Opus 5.5 在 56 项隐藏测试中仅得 48.3%。研究指出复杂工程里约束彼此耦合，解决一个问题常常导致另一个问题失败。

#### 技术亮点 / 影响分析
- **两条指向同一件事**：素材能不能用（授权链）与方案能不能落地（全部硬约束同时满足），才是「能生成」之后真正的门槛。
- **91% → 41.3% 的落差**：单点评测会系统性高估 Agent 在真实项目里的可用度；营销物料的审校不能只看「每条要求都过了」，要看整份成品是否同时过合规、品牌、法务与版位。
- **授权正在变成基础设施**：Anthropic 从被诉方转向付费授权方，说明训练 / 检索内容的来源可追溯性正成为模型厂商的固定合规成本项，与 11-02 期四巨头统一 robots.txt 退出信号是同一条主线。
- **边界**：PLE 为 Google / Mercor 自评基准，隐藏测试集未公开；AP 协议的金额、范围与期限均未披露，不宜按「全面和解」解读。

#### 三句话总结
1. Anthropic 与美联社签下首份新闻内容授权协议；Google PLE 测试实测工程 Agent 平均满足 91% 单项约束，但只有 41.3% 设计项跨过全部硬门槛。
2. 行业开始把「能生成」与「能合规、能整份交付」分开计量，单点跑分不再是可用度证明。
3. **对 CODM 宣发团队**：AI 素材上线前除单点验收外，还要补一整份「授权链 + 品牌规范 + 法务 + 版位」同时满足的终审清单——这恰恰是 91% 到 41.3% 中间那 50 个百分点。

## 编辑点评

八条其实在讲同一个动作：**交付物从「参数表」变成了「能跑起来的东西」**。前三名分别是开源基座、下周开权重的模型、把 Harness 做成云服务的厂商，第七条则是被真实调用量压着扩容十倍——模型侧第一次集体不再比谁更大，而是比谁**能被拿去用**。中间三条生成工具更直接：15 秒 + 降价三成 + 对话式改片、插件钻进 Premiere 时间线、实时数字人砍掉一半 GPU，全都指向「进工作流」而不是「出 demo」。
