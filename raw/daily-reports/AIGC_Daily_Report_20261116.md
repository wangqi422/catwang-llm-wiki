### #1 ⭐ Claude Fable 5.2 不调用图像模型，用 Python 代码逐笔作画：约 70 万笔触画照片级购物车

> **来源**：[IT之家 / 腾讯新闻](https://news.qq.com/rain/a/20261116A04BUY00) · [IT时代网 / 腾讯新闻](https://news.qq.com/rain/a/20261116A04SAF00) · [网易](https://www.163.com/dy/article/LBRISQUG05561FZL.html) · [ExplainX](https://www.explainx.ai/blog/claude-fable-5-2-simulated-brushstroke-painting-code-engine-2026) · [What The Future](https://whatthefuture.ai/blog/claude-fable-5-2-builds-paintings-one-brushstroke-at-a-time) · [aihot.news](https://aihot.news/items/mc0spd5j68n84jb96dj0euekq) | **评分**：9.4/10 | **标签**：确定性创作 / 代码画笔 / 生成路径 / P0

#### 核心事件
11 月 15–16 日，Anthropic 员工集中展示了 Fable 5.2 一种「异类 AI 生图」能力并引发中文科技媒体刷屏：**不调用任何扩散 / 图像生成模型**，而是**编写 1000–2000 行 Python**，在虚拟画布上模拟真实画笔的刷毛纹理、颜料湿度与画布质感，把画面拆成大量独立笔触坐标指令逐笔执行。开发者 **Jake Eaton** 要求「画一幅尽量接近照片」的作品，最终得到一辆**停车场里的购物车，用了约 70 万次模拟笔触**；他强调这些画**没有外部图像模型、没有预渲染或描摹底图**，每幅画本质就是一段可运行的 Python 程序，通过自写绘画引擎控制不同笔刷。工程师 **Michael Graczyk** 做了更硬的约束实验：画「日出时的鸟」时**只允许用代码模拟笔刷物理**，每一笔单独输出为坐标、**落笔后不能撤销**，21 秒视频记录全程共 **111 笔**——第一笔用 `#30346a` 色号、90px 笔宽、5 个轻微抖动路径点，模型自述约 7px 摆动是刻意的「人的手臂画不出绝对直线」。另一幅 280 笔的黄昏场景里，后期光照糊掉了桌上的颜料管与杯子，模型主动用新笔触重画，还让两个人物各用外侧手作画、好让内侧肩膀按提示词相触。Eaton 还让模型自造有虚构经历与稳定风格的「艺术家人格」（如专画零售公园阴天的 `Dermot Hale`、海岸题材 `The Tidewright`），以避开 Opus 5.5 曾因模仿现有画风挨的批评。

#### 技术亮点 / 影响分析
- **这是「生成式」之外的第二条路，而且天然可编辑**：扩散模型是「从噪声一次性出像素」，改一个细节得整张重抽；代码作画是**逐笔可寻址的程序**——logo 要放大、节奏要变、结尾要改，改坐标重跑即可，不靠「再抽一次卡看脸」。确定性、可版本控制、可局部重绘，正好补上生成模型在商业化物料里最被诟病的一致性缺口。
- **「观察画布 → 发现错误 → 覆盖修正」是一次完整的 agentic loop**：no-undo 约束把每一步都变成不可回退的决策，模型必须预判一笔对全局的影响、并决定后续哪笔能补救。Anthropic 把 Fable 5.2 定位为「复杂长程技术任务」模型（协调多子智能体、反复验证），作画只是这套能力最直观的可视化，官方称其在两个黑洞物理开放问题、三款电子设备设计、以及用 1000+ 子智能体八天写出一台笔记本操作系统等任务上均有结果。
- **别把 demo 当产品规格**：70 万笔、1000–2000 行、111 笔都是 Eaton / Graczyk 自报的演示元数据，不是 Anthropic 的产品参数；逐笔输出坐标极耗输出 token，成本与时长随「野心」线性放大。RoboDojo Sim 上 Fable 5.2 报 64.9% vs GPT-6 Astra 29.8%，但真实机械臂测试中 Astra 画得更快、且目前只有它能把多米诺立起来——**仿真强 ≠ 物理精细控制强**，边界要写清。
- **查重说明**：Fable 5.2 / Mythos 5.2 模型本身发布于 **11-09**，归档近 15 期未把「模型发布」作为条目报道；今日报的是 **11-15/16 集中曝光的「代码逐笔作画」能力与工程复现方法**，属新事件而非旧闻复读。11-13 期报的 Opus 5.5 转正是不同模型、不同事件。

#### 三句话总结
1. Anthropic 员工让 Fable 5.2 不调用图像模型，改用 1000–2000 行 Python 模拟画笔逐笔作画，约 70 万笔触画出照片级购物车、111 笔在「不可撤销」约束下画出日出鸟，并会观察画面自行纠错。
2. 它把「生成」换成了「编程」：每一笔是可寻址坐标、整幅画是可运行程序，确定性、可版本控制、可局部重绘，和扩散模型的「重抽卡」是两条完全不同的生产逻辑。
3. **对 CODM 宣发团队**：这类「代码即画笔 / 网页即画面」的路线最值得马上试的是**品牌一致性物料**——主视觉、角色立绘、赛季 KV 若要求改字、改色、改构图而不许跑偏，程序化生成比逐张抽卡更可控；建议用小样验证「改一处坐标 → 局部重渲染」的工作流，但把 70 万笔 / 1000 行代码的自报数据当演示、不当产能承诺，也不把仿真跑分写进对外物料。

### #2 1.4M 纯 HTML 3D 游戏走红：约 700KB 是打包的 Three.js，其余全程序化生成、零图片零模型

> **来源**：[公众号：数字生命卡兹克 / aihot.news 热度榜 02](https://aihot.news/items/izdx1kuppob6c65ghvmyeal38) · [AI HOT 聚合池](https://aihot.news/) | **评分**：8.9/10 | **标签**：程序化生成 / 单文件交付 / 提示词模板 / P1

#### 核心事件
11 月 16 日 aihot.news 热度榜第 2 位（评分 72），一个近期在群里疯传的 **1.4M 单文件纯 HTML 3D 游戏**被「数字生命卡兹克」拆解：作者指出其中**约 700KB 其实是打包进 HTML 的 Three.js 库**，剩下部分**全部由代码程序化生成**——没有图片、没有 3D 模型、没有录音，场景、材质、几何体、交互逻辑都在一份文件里由 JS 现场算出来。文章不仅讲清体积构成与 Three.js 程序化生成原理，还给出**可直接复用的提示词模板**与「自查 → 迭代」的调试方法，把「一个能跑的 3D 场景」降维成「一段可让模型反复改的 HTML」。

#### 技术亮点 / 影响分析
- **它和 #1 是同一件事的两个尺度**：Fable 5.2 是「用代码算出一幅静态画」，这个是「用代码算出一个可交互的 3D 世界」，再往下 #3 是「用代码算出一段视频」。今天最清晰的信号不是某个模型更强，而是**视觉产出正在从「采样」往「计算」迁移**——只要能写成代码，就能确定、能复现、能 diff。
- **单文件交付是被低估的分发优势**：一个 .html 双击即开、无需构建、无需 CDN、可离线、可直接塞进落地页或企微 H5，对「轻互动宣发物料 / 小游戏试玩 / 活动页」这种短周期、强传播、要到处嵌的场景，比一整套资源包轻得多。
- **提示词模板 + 自查迭代才是可复用的部分**：真正值钱的不是这个游戏，而是「怎么让模型一次性生成可运行场景、跑不通时怎么让它自己读报错修」的工作流。这与用户侧「用工程约束驾驭模糊系统」的思路完全一致。
- **边界**：1.4M / 700KB 为拆解者口径，非官方规格；程序化生成在复杂美术风格、写实贴图、大体量资产上仍远不及现成资源，适合几何 / 风格化 / 概念验证，别当成「替代美术管线」；单文件含第三方库时注意许可证与体积合规。

#### 三句话总结
1. 一个 1.4M 纯 HTML 3D 游戏被拆解：约 700KB 是内联的 Three.js，其余场景、几何与交互全由 JS 程序化生成，零图片零模型零录音，并附带可复用提示词模板与自查迭代法。
2. 它与 #1 / #3 共同印证「视觉产出从采样转向计算」——能写成代码就能确定、能复现、能局部改，且单文件 HTML 天然适合离线、嵌入式、轻互动分发。
3. **对 CODM 宣发团队**：这是今天最容易落地的一条——用一个下午把「赛季概念小场景 / 武器 3D 预览 / 活动页互动背景」做成单文件 HTML 试玩页，嵌进 H5 或企微卡片即可传播；把卡兹克的提示词模板收进团队的「场景生成 Prompt 库」，但写实贴图与正式美术资产仍走原有管线，别用程序化几何硬顶。

### #3 代码化视频工具链成形：HeyGen 开源 HyperFrames、cinecode 再登 GitHub 趋势榜、Remotion Agent Skills 30 分钟出片

> **来源**：[The Agent Times · HyperFrames](https://theagenttimes.com/agents/article/heygen-open-sources-hyperframes-giving-us-a-deterministic-vi-10740a56) · [dev.to · cinecode](https://dev.to/shakeelahmed/claude-code-can-now-direct-whole-films-from-code-meet-cinecode-4pkl) · [HM.AI · Remotion Agent Skills](https://www.haomings.com/ai/polymarket-remotion-agen/) · [GitHub 月榜](https://githubtrending.today/monthly) | **评分**：8.7/10 | **标签**：视频基建 / 智能体原生 / 确定性渲染 / P1

#### 核心事件
11 月中旬，「把视频变成可调用的代码原语」在同一周集中成形：① **HeyGen 开源 HyperFrames**（Apache 2.0），把任意用 **HTML + CSS + JavaScript** 写的场景，经 Puppeteer（浏览器渲染）+ FFmpeg（编码）+ GSAP / Lottie（动画）**本地渲染成 MP4**，主打**逐帧确定性**——同样的输入必得同样的输出，且 agent-native、无需 API key、可与 Claude Code 等编码智能体直接配合，GitHub 月榜显示 `heygen-com/hyperframes` 已约 84.7K stars、月增约 2.1 万。② 开源技能包 **cinecode**（MIT，11-03 建仓、11-09 约 1.7K stars、**11-15 再登 GitHub 趋势榜约 2.5K**）让 Claude Code / Cursor「从代码导演整部电影」：五阶段 Plan → 剧本分镜 → 用 Canvas 2D / three.js 把每帧写成时间的纯函数 → Headless Chrome 逐帧捕获 → Web Audio 离线混音到 -14 LUFS 再 mux 成 MP4，**不用视频模型、不用渲染队列、不烧积分**，还带 Quick / Film 双模式与「先出两张静帧 + 低清草稿、留两轮改稿」的审批闸。③ **Remotion Agent Skills** 演示用 4–5 轮提示、约 30 分钟产出一条完整 Polymarket 宣传片，把「prompt → 成片」压进一次对话。

#### 技术亮点 / 影响分析
- **三者拼出一条完整替代链**：#1 是静态画、#2 是可交互 3D、这一条是**成片**——共同点是「不调用生成式视频模型，改用代码确定性渲染」，代价是要写代码，收益是**可编辑、可版本控制、可批量改价改字改结尾**，恰好打中扩散视频「改一处全片重抽、角色脸会变」的老大难。
- **「确定性」才是能进流水线的关键**：自动化宣发、批量本地化（多语种字幕 / 多地区价格 / 多版本 A/B）要求同一模板稳定复现，非确定性生成模型很难做回归测试；HyperFrames 的逐帧一致与 cinecode 的「改代码重渲染」把视频拉近了软件工程的 CI 范式。
- **审批闸值得抄**：cinecode 在昂贵的全片渲染前先给静帧 + 低清草稿、留两轮修改——这是把「人工审片」前置到最便宜的时刻，对任何自动化内容流水线都是可直接复用的成本控制设计。
- **边界**：cinecode / Remotion 案例均为作者自述（30 分钟、4–5 提示、星数随时间变化），非独立评测；这类工具擅长信息流广告、数据可视化、倒计时 / 预热、Motion Graphics，**复杂叙事、情感长片、写实人物仍要专业剪辑与实拍介入**；生成的配音 / 音效须过版权审查，品牌调性须人工把关。

#### 三句话总结
1. HeyGen 以 Apache 2.0 开源 HyperFrames（HTML/CSS/JS → 逐帧确定性 MP4、agent-native），cinecode 11-15 再登 GitHub 趋势榜（用 three.js / Canvas 把电影写成代码、MIT），Remotion Agent Skills 演示 30 分钟 4–5 提示出一条宣传片。
2. 三者与 #1 / #2 合起来，标志「视觉产出从采样转向计算」已覆盖画、3D、视频全链：换来的确定性、可版本控制、可局部重渲染，正是批量与本地化宣发最需要的能力。
3. **对 CODM 宣发团队**：优先拿它做**可批量复用的模板化短片**——多语种字幕、多地区价格、赛季倒计时、数据战报这类「同版式换内容」的物料，改数据重渲染即可出 N 个版本；把 cinecode 的「静帧 + 草稿审批闸」写进自动化出片 SOP，但写实人物、情感叙事和配音版权仍走人工，别把 30 分钟出片当产能承诺。

### #4 ⭐ 美团开源 LongCat-2.5 权重：1.6 万亿 MoE 全程昇腾训练、未用一块英伟达 GPU，194 块 Atlas A2 参考部署

#### 核心事件
11 月 15 日，中国科学院自动化研究所联合**美团**、山东大学、中国人民大学、中科院微电子所、上海交通大学、理想汽车等单位发布 **LLM Agent 递归自我改进（Recursive Self-Improvement, RSI）综述**《When, Where, and How Experience Becomes Structure》。核心命题：**模型权重不变，Agent 也能积累能力**——把一次任务里留下的工具调用记录、执行结果、用户纠正、失败修复，转化为下次能用的结构。综述沿 **Prompt 优化 / Memory 进化 / Skill 进化 / Harness 进化**四条主线，用**三个问题**（何时该改、改哪里、怎样把经验变成经得起验证、能长期复用的改进）与**七步生命周期**串起框架，选取 **40 项代表性研究**绘制全景、对 **20 项**研究的具体更新闭环做对照分析。同期 GitHub 11-15 趋势榜被概括为「AI 生产力与 Agent 协作的**接口之战**」：**Univer** 开源「面向人与 AI Agent」的 Office SDK、**AG-UI** 定义智能体—前端交互协议、**腾讯 LoopForge**（Go、自托管）编排多个 coding agent 并带**人工审批闸**、plannotator 登顶——都是把「经验 / 协作」沉淀成可复用接口的同一股方向。

#### 技术亮点 / 影响分析
- **它给「越用越强」提供了工程语法**：过去谈自我改进容易滑向玄学，这篇把它拆成四个可分别落地的层——改一句 Prompt、存一条 Memory、固化一个 Skill、调整 Harness 的工具接口与检查逻辑，且强调「经得起验证」而非「改了就算改进」。对做日报 / 巡检 / 舆情这类常驻 Agent 的团队，这是一份可直接对照的自检清单。
- **Harness 进化与「人工审批闸」是今天最实用的一格**：#3 的 cinecode 在昂贵渲染前留两轮改稿、腾讯 LoopForge 在编排里放人工审批，本质都是把「验证」做成流程节点而非事后补救——与综述「经验 → 经验证的结构」是同一句话的两种实现。
- **与用户侧知识复利体系同构**：把一次任务的失败修复沉淀成 Skill / 规则、并按「是否被再次使用」而非「是否写下来」衡量价值，正是「积累而非检索」的工程版；四主线可直接映射到团队的 Prompt 进化库与 Skill 评估维度。
- **边界**：这是**综述 / 框架**而非新模型或新基准，不含可直接跑的实现与实测提升；40 项研究的对照多为定性归纳，「自我改进」在开放环境下的稳定性、错误累积与回滚仍是开放问题；GitHub 星数与榜单为 11-15 快照、随时间变化。

#### 三句话总结
1. 中科院自动化所联合美团等发布 LLM Agent 递归自我改进（RSI）综述，以 Prompt / Memory / Skill / Harness 四主线、三个问题、七步生命周期梳理 40 项研究，核心是「权重不变，Agent 也能把经验变成可长期复用的结构」；同期 GitHub 趋势榜以 Univer / AG-UI / 腾讯 LoopForge 呈现「接口之战」。
2. 它给「越用越强」补上工程语法，并把「验证 / 人工审批闸」做成流程节点——与 #3 的静帧审片闸、以及「积累而非检索」的知识复利思路完全同构。
3. **对 CODM 宣发团队**：把综述四主线做成常驻 Agent（日报、竞品巡检、素材打标）的自检表——每次失败修复先问「该沉淀成 Prompt / Memory / Skill / Harness 哪一层」，并以「30 天内是否被再次调用」而非「是否记录」衡量价值；同时给所有自动化出片 / 发布流程保留一个人工审批节点，别让「自我改进」跳过审片与合规。

## 编辑点评

八条其实在讲同一件事：**不调模型调代码，不靠 CUDA 靠昇腾，都在把创作与算力从别人定价的地方挪回自己手里**。第 100 期恰逢周一，大厂集体没发新旗舰，反而把这两条「去依赖」的路亮得格外清楚——前几期是「补账本、明码标价」，今天更进一步：不只要算清成本，还要把生产资料的**控制权**换回来。

**① 上半场（#1–#3）是「代码即画笔」的三个尺度**。**Fable 5.2 用 70 万笔触画购物车**（#1）证明不调图像模型也能出照片级作品，而且每一笔是可寻址坐标；**1.4M 纯 HTML 3D 游戏**（#2）把同样的思路推到可交互世界，还附赠提示词模板；**HyperFrames / cinecode / Remotion**（#3）补齐成片，把视频变成可版本控制的确定性渲染。三者共同点不是「更强」，而是**确定、可复现、可局部改**——改 logo 不用重抽卡，改价格不用重拍片。对要批量、要本地化、要品牌一致性的宣发，这比多几个 Elo 分实在得多。

**② 下半场（#4–#6）是「国产算力栈」的因果闭环**。**美团把 1.6T 的 LongCat-2.5 权重放进 MIT，并首次完整披露「全程昇腾、194 块 A2、无英伟达选项」**（#4），是 11-02「亮相」之后的兑现新阶段；**华为云同晚上线 openPangu-2.1-Pro**（#5），用鸿蒙场景与昇腾算子生成补齐工具链；而**美国国会正把三项管制写进 NDAA、连云端租算力都要许可**（#6）。一边锁、一边自建，两件事摆在同一天，比任何「国产替代」的口号都更有说服力——但也要克制：88.4 是厂商自报、法案尚无成文文本，两个都不能写死进对外承诺。

**③ 收尾两条（#7–#8）是账本与复利**。**澳央行 / Gartner / 斯坦福三份数据彼此对撞**（#7），提醒「净增 170 万」与「年轻软件岗先受冲击」并不矛盾，是三把不同的尺；**RSI 综述**（#8）则把「Agent 把经验变成结构」拆成 Prompt / Memory / Skill / Harness 四层。有意思的是，#7 说被结构化最深的恰是模板化白领产出，#8 就给出「把每次修复沉淀成可复用结构」的方法——今天这两条其实是一问一答。

一组对照值得记：**#1 的「落笔不可撤销」、#3 的「静帧审批闸」、#8 的「人工审批 + 经验证才叫改进」，都在做同一件事——把「验证」前置到最便宜的时刻**。逐笔作画不许反悔，所以每一笔都得预判；全片渲染前先出草稿，所以改稿不烧钱；经验要先通过验证才配沉淀成 Skill。今天没有谁更聪明，比的是谁先把「不可逆」的成本管住。

一句话：不调模型调代码，不靠 CUDA 靠昇腾，都在把创作从最贵的供应链上挪开

今天最高分给到 **#1 Fable 5.2 代码逐笔作画（9.4 / P0）**：分量不在「画得像照片」，而在它给出了生成式之外的第二条可商业化路径——每一笔是可寻址坐标、整幅画是可运行程序，确定性、可版本控制、可局部重绘，正好补上扩散模型在品牌一致性物料里最被诟病的缺口；且与 #2 / #3 连成画、3D、视频的完整光谱，是今天唯一一条能直接改写宣发工作流的线索。

五条可以立刻执行的线索：**① 用一下午做「单文件 HTML 概念小场景」试玩页**（赛季概念 / 武器 3D 预览 / 活动页背景），嵌进 H5 或企微卡片，把卡兹克的提示词模板收进团队 Prompt 库；**② 把模板化短片（多语种字幕 / 多地区价格 / 倒计时 / 数据战报）迁到「改数据重渲染」的确定性工具链**，并把「静帧 + 草稿、留两轮改稿」的审批闸写进自动化出片 SOP；**③ 云渲染 / 批量出图 / 长周期 GPU 合同的预算与排期，标注「12 月 NDAA + 出口管制 + 12/1–12/3 听证」外部变量**，不把特定加速器供货与价格写死进对外承诺；**④ 所有厂商自报数据（LongCat 88.4 / 194 块昇腾 / 70 万笔 / 30 分钟出片）一律标「演示 / 自报、未经第三方复测」**，不进对外承诺、不按单价或跑分直接排名次；**⑤ 把 RSI 四主线做成常驻 Agent 自检表**，以「30 天内是否被再次调用」衡量沉淀价值，并给所有自动化发布流程保留人工审批与合规审片节点。
