## 🛠️ 实用工具箱 (Tools & Apps)

### 1. OpenAI Codex Record & Replay — 录制操作，一键生成可复用 Skill

OpenAI 为 Codex 加上了 Record & Replay 功能：你在沙箱环境里操作一遍（比如"创建项目→配置环境→跑测试"），Codex 自动录制每一步，然后生成一个可复用的 Skill 文件。下次直接调用 Skill，Agent 就能自动完成同样流程。这是 AI 编程从"对话式"到"工作流式"的关键一步。

- **获取方式**：Codex CLI 最新版 → 输入 `/record` 开始录制 → 操作完毕 → 自动生成 `.skill` 文件
- **上手建议**：先录一个你每周重复做的任务（如项目初始化、日报生成），看 Skill 文件质量，再逐步扩展到复杂流程
- **Source**: *@OpenAI*

### 2. ChatGPT 定时任务 — 告别手动触发，AI 按计划自动执行

ChatGPT 上线 Scheduled Tasks 功能：设置定时触发，AI 到点自动执行。支持两种模式——① 周期任务（每天/每周固定时间运行）② 监测任务（定期检查某个条件，满足时通知你）。替代了之前需要第三方 Pulse 服务的场景，直接在 ChatGPT 内完成。

- **获取方式**：ChatGPT Plus/Pro → 设置 → Scheduled Tasks → 创建任务
- **上手建议**：先设一个简单的每日监测任务（如"每天 9 点搜索 AI 新闻并总结 3 条"），跑通后再加复杂逻辑
- **Source**: *@OpenAI*

## ⚡ 高效工作流 (Workflows & Hacks)

### 4. Karpathy Guidelines — 4 条规则让 AI 编程从"赌运气"变"可控"

Karpathy 在 GitHub 22 万星项目 `karpathy/llm-wiki` 中更新了 AI 编程四原则，实测将任务成功率从 59% 提到 97%。核心思路：AI 能做的远多于它应做的——克制即智慧。四条规则是：① 先想再写（Think Before Coding）② 先求简单（Simplicity First）③ 外科手术式改动（Surgical Changes）④ 目标驱动（Goal-Driven Execution）。

**痛点场景**：AI 编程最大的坑不是"不会做"，而是"做得太多"——顺手重构、过度抽象、引入不必要依赖。

**AI 解决路径**：
1. 把四原则直接写进 CLAUDE.md 或系统提示词
2. 每次对话开头 AI 先复述需求，确认理解后再动手
3. 改动后列出"改了什么 / 为什么 / 怎么验证"，而非直接甩代码

**预期效果**：Bug 引入率从 22% 降到 3%，Code Review 一次通过率翻倍。

*Source: @karpathy*

### 5. AI-First 工作流四层架构 — 从"用 AI"到"AI 驱动"的系统化落地

本周多篇实战文章总结出 AI-First 工作流的四层架构模型：**Intelligence 层**（模型选型+Prompt 工程）→ **Orchestration 层**（Agent 编排+工具调用）→ **Knowledge 层**（RAG+知识库+记忆）→ **Development 层**（CI/CD 集成+自动化测试）。不是"先做哪个"，而是"四层同时设计，缺一不可"。

**痛点场景**：团队想"全面 AI 化"，但今天试 Prompt、明天接 Agent、后天搞 RAG，拼不出完整系统。

**AI 解决路径**：
1. **Intelligence**：选 1 个主力模型（Claude/GPT-4o），统一 Prompt 规范（用 RCCF 框架）
2. **Orchestration**：从单 Agent 起步，确认稳定后再加 fan-out 多 Agent
3. **Knowledge**：先用本地 Markdown 知识库，验证检索质量后再上向量数据库
4. **Development**：先手动触发 AI 任务，稳定后再接入 CI/CD 自动化

**预期效果**：从碎片化 AI 使用到系统化 AI 工作流，3 个月内团队 AI 化覆盖率达到 80%。

*Source: @swyx, @amasad*

### 6. Make + AI Agent 三级进阶 — 从单步自动化到全流程 Agent 编排

Make（原 Integromat）本周更新 AI Agent 集成指南，三级进阶路径：**Level 1** — 单步自动化（触发器→AI 模块→输出，如"收到邮件→GPT 摘要→发 Slack"）；**Level 2** — 多步链式（串联 3-5 个 AI 模块，带条件分支，如"监控竞品→分析→生成简报→推送"）；**Level 3** — Agent 自主编排（AI 自行决定调用哪些工具、什么顺序，Make 做执行层）。

**痛点场景**：知道 AI 能自动化，但不知道怎么从 0 到 1 搭建，总想一步到位搞 Agent。

**AI 解决路径**：
1. **Level 1 起**：先做一个最简场景（日报摘要 / 竞品监控），跑通再说
2. **Level 2 扩**：把 Level 1 的输出接入下一个 AI 模块，形成链式处理
3. **Level 3 进**：给 AI 定义工具列表和边界，让它自行编排执行

**预期效果**：Level 1 半天上线，Level 2 一周搞定，Level 3 一个月打磨。不要跳级。

*Source: @rauchg, Make 官方文档*

## 🧠 方法论与 Prompt (Methods & Prompts)

### 7. Claude Fable 5 提示词逆向 — 12 万字泄露里的 7 个可抄技巧

Claude Fable 5 系统提示词被完整泄露（约 12 万字），从中提炼出 7 个可立即使用的 Prompt 技巧：

**核心理念**：顶级 AI 的"思考说明书"就是最好的 Prompt 教材——看它怎么约束自己，你就怎么约束它。

**7 个可抄技巧**：

1. **正反清单法**：不只说"要做什么"，还要说"不要做什么"——约束反面比正面更有效
2. **硬编码规则**：关键规则用 `ALWAYS` / `NEVER` / `MUST` 标记，而非"尽量""建议"
3. **搜索决策流程**：定义"何时搜索 vs 何时直接回答"的判断树，避免 AI 每次都搜索浪费时间
4. **分阶段输出**：先思考→再规划→最后执行，不要一步到位
5. **自检清单**：输出前过一遍 Checklist（完整性、准确性、格式），而非生成即交
6. **上下文窗口管理**：长对话中定期总结前文，防止信息稀释
7. **工具调用协议**：定义调用外部工具的固定格式和错误处理流程

**Prompt 模板**（综合技巧 1+2+4）：

```
你正在执行 [任务描述]。

## 必须遵循（ALWAYS）
- [规则1]
- [规则2]

## 绝对禁止（NEVER）
- [禁止1]
- [禁止2]

## 执行阶段
1. 思考：复述需求 + 列出关键约束
2. 规划：输出执行步骤（不超过 5 步）
3. 执行：按规划输出最终结果
```

*Source: @AnthropicAI (泄露文档逆向分析)*

### 8. DeepSeek 隐藏玩法 — 角色+思维链三段式 / 费曼学习法摘要

社区总结出 DeepSeek 的两个高效用法：

**核心理念**：DeepSeek 的思维链是"可设计的"，不是让它自己想，而是你规定它怎么想。

**玩法 1 — 角色+思维链三段式**：

```
你是 [具体角色：如"10 年经验的 FPS 游戏运营"]。

请按以下三段式思考：
1. [事实层]：列出你已知的相关事实和数据
2. [分析层]：基于事实进行逻辑推理，标注确定性（高/中/低）
3. [结论层]：给出可执行建议，每条附带前提条件

任务：[你的问题]
```

**玩法 2 — 费曼学习法摘要**：

```
请用费曼学习法总结以下内容：
1. 用最简单的话解释核心概念（假设读者是初中生）
2. 找出一个最反直觉的要点
3. 给出一个"如果...那么..."的实操建议

内容：[粘贴长文]
```

**实战案例**：用三段式分析"CODM S39 赛季宣发策略"——事实层列出历史数据、分析层推理趋势、结论层给出 3 条带前提的具体建议，比直接问"帮我分析"输出质量高 3 倍。

*Source: @deepseek_ai 社区实战*

### 9. 反直觉 Prompt 逆向论证 — 先问"为什么不该做"

本周热议的 Prompt 框架：在让 AI 执行任务前，先让它论证"为什么不应该做这件事"。看似多此一举，实则解决 AI 最常见的两个问题——① 过度执行（不该做的也做了）② 缺乏边界意识（不知道在哪里停）。

**核心理念**：AI 的错误 80% 来自"做了不该做的事"，而非"没做该做的事"。

**Prompt 模板**：

```
任务：[描述你要做的事]

在执行前，请先回答：
1. 这个任务有哪些潜在风险或副作用？
2. 在什么情况下不应该执行这个任务？
3. 如果只能做 50%，最应该保留哪部分？最应该砍掉哪部分？

确认以上后，再执行任务。
```

**实战案例**：让 AI 重构一个模块——不加逆向论证时，AI 顺手改了 5 个文件的依赖关系（不该动的动了）；加了逆向论证后，AI 先列出"改 A 会影响 B 和 C，风险中等"，你确认后再动手，改动精确且无副作用。

*Source: @swyx, @karpathy*
